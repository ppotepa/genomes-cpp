======================================================================
PUBLIC CONTRACTS
======================================================================
1. EntityId is generational runtime identity: index + generation; optional PersistentEntityId is separate semantic StrongId when save/network persistence needs it.

2. ComponentTypeId is compile-time/stable registration ID with size/alignment/move/destroy function table. Registration freezes before simulation begins.

3. ChunkStorage owns fixed-capacity SoA columns for one archetype signature. Entities in a chunk share component set; component columns are contiguous/aligned.

4. Structural changes are not performed while systems iterate chunks; command buffer stage owns moves/create/destroy.

======================================================================
DATA LAYOUT
======================================================================
Entity table: generation + archetype/chunk/row location. Chunk header cold metadata + entity IDs + separate aligned columns. Target chunk payload 16-64 KiB benchmarked; initial default 32 KiB.

CREATE SLOT:
    idx := freeList.pop or entityTable.size
    generation := max(1,table[idx].generation)
    return EntityId(idx,generation)

CHUNK REMOVE row:
    last := count-1
    destroy removed row components
    if row != last:
        for column: move last -> row
        movedEntity := entities[last]
        entities[row] := movedEntity
        table[movedEntity].row := row
    count--

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Entity table structural writes happen in commit phase. Systems own disjoint component write sets/chunks according scheduler; readers see stable structure during phase.

======================================================================
ERROR HANDLING
======================================================================
Invalid/stale entity handles and illegal structural mutation return typed errors or development assertions; expected gameplay failures are not exceptions.

======================================================================
DETERMINISM RULES
======================================================================
Entity creation semantic order resolved in command commit; internal chunk row can change via swap-back and is never semantic ordering.

======================================================================
PERFORMANCE RULES
======================================================================
SoA columns, chunk iteration contiguous, no per-component heap object.

MIGRATION / COMPATIBILITY
