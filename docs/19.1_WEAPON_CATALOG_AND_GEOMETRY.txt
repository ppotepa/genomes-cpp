======================================================================
PUBLIC CONTRACTS
======================================================================
1. WeaponDefinition is immutable catalog data with stable WeaponId, category,
firearm flag, compatible ammunition IDs where applicable, grip/profile
capabilities, dimensions and procedural visual parameters.

Non-firearms are first-class:
    knife   -> ONE_HANDED / 1H / firearm=false
    grenade -> ONE_HANDED / 1H / firearm=false

Their presence in WeaponCatalog does NOT imply firearm ammunition or projectile
spawn contract.

2. Weapon geometry generation consumes WeaponDefinition + ItemInstance seed/variant and produces backend-neutral MeshData/attachment landmarks (muzzle, grips, sights, stow anchors).

3. Weapon geometry is representation, not ballistics authority. Ballistics uses WeaponId/Ammunition IDs and shot parameters from gameplay contracts.

4. Catalog does not require Infantry; another unit type may carry/use a
WeaponDefinition if it implements required handling capability.

Pinned SOURCE catalog count is 8 entries and is verified as migration data, not
baked into generic engine limits.

5. All dimensions are metres and explicit; geometry may be stylized and is not a manufacturing/mechanical model.

======================================================================

======================================================================
PSEUDOCODE
======================================================================
BUILD:
    def := catalog.require(id)
    key := H(def.version, id, itemVariant)
    if cache hit: return artifact
    recipe := generatorFor(def.category).build(def.visual, itemVariant)
    attach := deriveAttachments(def, recipe)
    validate(recipe, attach)
    return cache.commit(key, artifact)

CATALOG VALIDATE:
    unique WeaponId
    firearm -> compatibleAmmo nonempty
    each grip/profile supported
    dimensions finite positive
    required muzzle/grip landmarks present
