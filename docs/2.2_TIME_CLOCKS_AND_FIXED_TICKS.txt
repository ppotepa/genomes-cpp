======================================================================
PUBLIC CONTRACTS
======================================================================

1. Duration

Use std::chrono-based internal representation.

Canonical high precision type:

    using Nanoseconds = std::chrono::nanoseconds;

Conversions to floating seconds happen only at explicit boundaries.


2. SimulationTick

Strong integer tick counter:

    using SimulationTick = StrongId<SimulationTickTag, uint64_t>;

IMPORTANT:
    StrongId validity semantics make 0 invalid for many IDs, but simulation tick
    zero IS meaningful.

Therefore DO NOT use StrongId directly if its zero-invalid semantics conflict.

Preferred dedicated value type:

    struct SimulationTick
    {
        uint64_t value = 0;
    };

Tick zero = initial simulation state.


3. FixedStepConfig

    fixedStep      = 1/60 s
    maxSteps       = 8
    maxFrameDelta  = 250 ms

Use integer duration representation for fixedStep.

DO NOT round 1/60 to one integer nanosecond step and repeatedly subtract it.
16,666,667 ns accumulates a systematic +20 ns per 60 ticks.

Canonical simulation rate:

    FixedStepNumerator   = 1
    FixedStepDenominator = 60

Wall-time accumulation uses a rational phase accumulator. One robust integer
form when wall deltas are measured in nanoseconds is:

    phaseUnits += frameNanoseconds * FixedStepDenominator

One fixed tick is due whenever:

    phaseUnits >= 1,000,000,000 * FixedStepNumerator

and execution subtracts exactly that threshold from phaseUnits.

Thus 60 logical ticks represent exactly one rational simulation second even
though one wall-clock tick interval is not representable as integer ns.

Tick-based systems use SimulationTick as authoritative time identity.

Floating dt passed to physics/integration is derived explicitly as:

    double fixedDtSeconds = 1.0 / 60.0


4. FixedStepAdvanceResult

    stepsExecuted
    interpolationAlpha
    droppedTime
    consumedFrameTime


5. WallClock

Monotonic source only:

    std::chrono::steady_clock

Never system_clock for frame delta.


======================================================================
DATA LAYOUT
======================================================================

FixedStepClock target state:

    optional<steady_clock::time_point> lastWallTime
    uint64/128-bit rational phaseUnits or checked equivalent
    nanoseconds droppedTimeTotal
    uint64_t totalSteps

The accumulator representation must preserve the rational 1/60 threshold
without repeatedly rounding a tick duration to nanoseconds.

No heap allocation per frame.

======================================================================
MATHEMATICAL CONTRACTS
======================================================================

Interpolation alpha:

    alpha =
        phaseUnits
        /
        (1,000,000,000 * FixedStepNumerator)

for the nanosecond-scaled rational representation, with:

    0 <= alpha < 1

after catch-up/drop handling.

Frame clamp:

    frame = min(rawFrameDelta, maxFrameDelta)

Dropped due to frame clamp:

    dropped += rawFrameDelta - frame

Catch-up cap:

    execute at most maxSteps fixed steps.

Remaining whole fixed steps beyond cap are dropped and counted.

IMPLEMENTATION STEPS
======================================================================

STEP 1 - Time.hpp

Define explicit conversion helpers:

    secondsToDuration(double)
    durationToSeconds(Duration)

Avoid implicit double <-> duration conversion in public APIs.


STEP 2 - WallClock

API:

    class WallClock
    {
    public:
        using TimePoint = std::chrono::steady_clock::time_point;

        [[nodiscard]]
        static TimePoint now() noexcept;
    };

No state.


STEP 3 - SimulationTick

Implement zero-valid value type.

Operations:

    value()
    increment
    equality/order
    difference only where semantically safe


STEP 4 - FixedStepConfig

Default native compatibility config:

    60 Hz
    max 8 steps
    250 ms max frame delta

Validate:
    denominator > 0
    maxSteps > 0
    maxFrameDelta > 0


STEP 5 - FixedStepClock

Methods:

    reset()
    advance(now, callback)

advance:
    calculates wall delta
    clamps
    accumulates
    invokes callback once per fixed step
    increments tick/step counters
    drops excess backlog after maxSteps
    returns interpolation alpha + accounting


STEP 6 - FIRST ADVANCE SEMANTICS

Preserve SOURCE behavior exactly at the wall-clock entry boundary:

    first advance sets last wall time
    executes zero simulation catch-up steps
    returns interpolation alpha = 1

SOURCE::js/core/fixedClock.js currently returns 1 on the first advance call.
This is presentation interpolation behavior, not a simulated tick.

The deterministic advanceBy(Duration) path has no implicit first-call special
case because the caller supplies an explicit delta.

Do not invent one fake simulation step on first timestamp.


STEP 7 - RESET

reset:
    clears accumulator
    clears last wall timestamp

Policy:
    total lifetime step count may either remain or reset only through explicit
    fullReset() API.

Preferred:
    resetTiming() preserves SimulationTick.
    resetAll() resets tick/accounting.

Avoid ambiguous reset semantics.


STEP 8 - DETERMINISTIC MANUAL DELTA PATH

Tests and headless simulation need no real wall clock.

Provide:

    advanceBy(Duration frameDelta, callback)

This path performs exactly the same accumulator/clamp logic without querying
steady_clock.

Wall-time overload should call into advanceBy.


STEP 9 - TEST LEGACY CASES

Cases:

    first advance -> alpha 1, zero steps
    exact one step
    half step -> alpha 0.5
    two steps
    large frame clamped at 250 ms
    max 8 steps catch-up
    excess full-step backlog dropped
    dropped-time accounting
    reset timing
    repeated accumulation
    no negative frame delta accepted


STEP 10 - LONG RUN TEST

Run 60 * 60 * 10 ticks = ten simulated minutes.

Assert:
    tick count exact.
    tick-derived simulation time exact as rational ticks/60.
    no cumulative dependence on wall-clock floating addition.


======================================================================
PSEUDOCODE
======================================================================

ADVANCE BY:

    function advanceBy(rawFrame):
        require rawFrame >= 0

        frame := min(rawFrame, config.maxFrameDelta)

        droppedTotal += rawFrame - frame
        accumulator += frame

        steps := 0

        threshold := 1_000_000_000 * FixedStepNumerator
        phaseUnits += frameNanoseconds * FixedStepDenominator

        while phaseUnits >= threshold
              and steps < config.maxSteps:

            callback(fixedDtSeconds, currentTick)

            phaseUnits -= threshold
            currentTick += 1
            totalSteps += 1
            steps += 1

        if phaseUnits >= threshold:
            wholeExcessTicks := floor(phaseUnits / threshold)
            droppedPhase := wholeExcessTicks * threshold
            phaseUnits -= droppedPhase
            droppedTotal +=
                rationalPhaseToDuration(droppedPhase)

        alpha :=
            phaseUnits / threshold

        return {
            stepsExecuted: steps,
            interpolationAlpha: alpha,
            droppedTime: droppedThisAdvance
        }


WALL ADVANCE:

    function advance(now):
        if lastWallTime is None:
            lastWallTime := now
            return {
                stepsExecuted: 0,
                interpolationAlpha: 1,
                droppedTime: 0
            }

        raw := max(now - lastWallTime, 0)
        lastWallTime := now

        return advanceBy(raw)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================

FixedStepClock has one owner.

Do not mutate one clock concurrently.

SimulationTick is copied by value.

WallClock::now is thread-safe through standard steady_clock.

Later simulation scheduler owns authoritative clock.

Renderer receives snapshots/timestamps, not mutable simulation clock ownership.

======================================================================
ERROR HANDLING
======================================================================

Invalid configuration:
    Result/typed error or constructor validation according to coding policy.

Negative manual delta:
    InvalidArgument.

steady_clock backwards anomaly:
    clamp raw delta to zero and diagnostic later through logging system.

======================================================================
DETERMINISM RULES
======================================================================

Authoritative semantic time:

    tick count

NOT:
    wall-clock timestamp
    renderer frame index
    accumulated double seconds

Simulation systems requiring elapsed time should prefer:

    ticks
or:
    explicit conversion from tick count/fixed rate.

======================================================================
PERFORMANCE RULES
======================================================================

advanceBy:
    O(number of executed fixed steps)
    max bounded by maxSteps.

No allocation.
No lock.
No virtual dispatch required.
