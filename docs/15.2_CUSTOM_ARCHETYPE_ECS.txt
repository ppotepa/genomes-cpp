======================================================================
PUBLIC CONTRACTS
======================================================================
1. Genomes uses custom archetype/chunk ECS; Flecs is not a runtime dependency. This decision prioritizes controllable memory layout, scheduler integration and no external semantic leakage.

2. Archetype key = sorted component type IDs; WorldEcs map lookup is cold/structural, hot iteration stores cached matching archetype list.

3. Query declares Required, Optional, Excluded and read/write access per component. Query compilation validates component types and builds chunk iterators.

4. Cold/large variable data is referenced by handles into domain stores, not stuffed into every hot entity component.

======================================================================
DATA LAYOUT
======================================================================
ArchetypeKey is the sorted stable set/hash of ComponentTypeId values.

Archetype storage:
    ArchetypeRecord[]
        ArchetypeId
        ComponentTypeId list/range
        Chunk[] / chunk handles

Chunk:
    fixed target payload size chosen by benchmark
    EntityId/generation column
    one contiguous aligned column per component
    count/capacity
    structural revision

Entity location table maps EntityId generation -> {ArchetypeId, ChunkId, row}.
Raw pointers into chunks never survive structural mutation boundaries.

PSEUDOCODE
======================================================================
QUERY ITERATION:
    plan := queryCache.get(signature/readWrite)
    for archetype in plan.matches:
        for chunk in archetype.chunks:
            pos := chunk.span<Position>()
            vel := chunk.span<Velocity>()
            for i in [0,count):
                pos[i] += vel[i]*dt

ADD COMPONENT:
    targetSig := sourceSig + type
    target := getOrCreateArchetype(targetSig)
    move common components sourceRow -> targetRow
    construct new component
    remove source row/update location

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Structural changes commit outside system iteration. Parallel system jobs split chunks; no two jobs write same component column/chunk unless explicitly partitioned.

======================================================================
ERROR HANDLING
======================================================================
Invalid/stale entity handles and illegal structural mutation return typed errors or development assertions; expected gameplay failures are not exceptions.

======================================================================
DETERMINISM RULES
======================================================================
Chunk/archetype storage order is not gameplay semantic order. Stable reductions/commands use EntityId/PersistentId.

======================================================================
PERFORMANCE RULES
======================================================================
Compiled query cache, contiguous spans, chunk granularity, no virtual Update. Benchmark bandwidth and cache misses later.
