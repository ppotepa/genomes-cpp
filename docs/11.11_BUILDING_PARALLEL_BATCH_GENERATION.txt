======================================================================
PUBLIC CONTRACTS
======================================================================
1. Each BuildingSiteRequest/BuildingId is an independent GenerationGraph
subgraph with child SeedPath and ScratchContext. No generator static mutable
scratch.

2. Batch output slots indexed/sorted by stable BuildingId. Failed individual building follows explicit city policy: retry with deterministic fallback spec/version, placeholder semantic record, or fail transaction—never silently disappear.

3. Memory concurrency limited by maxInFlightBuildings/scratch budget; scheduler does not start 10k heavy solvers simultaneously if memory budget exceeded.

4. Representation compilers may run after each plan or in separate batches; artifact cache prevents duplicate plan/compiler work.

5. Every successful output slot contains BuildingPlan plus the matching
BuildingSiteResolution. Both retain request/parcel correlation IDs. Cross-region
streaming reloads the stable plan identity and must not reroll the building.

======================================================================
DATA LAYOUT
======================================================================
Semantic plan arrays remain renderer/physics/nav independent. Compiler products are versioned artifacts keyed by BuildingPlan fingerprint.

IMPLEMENTATION STEPS

STEP 2

STEP 3

STEP 4
    Implement deterministic fallback chain with versioned reason codes.

STEP 5
    Compile render/collision/nav recipes in parallel after frozen plan; destruction structure already part of semantic model.

STEP 6

======================================================================
PSEUDOCODE
======================================================================
FOR request stable list:
    childSeed := citySeed.child("building", request.id)
    acquire memory budget token
    spawn:
        plan := generate(request,childSeed,scratch)
        if fail: plan := deterministicFallback(request, reason)
        validate/freeze
        in parallel compile render/collision/nav
        resolution := summarizeForCity(plan, request.accessIntent)
        outputs[stableSlot(request.id)] := plan,resolution,artifacts
        release token
wait all
verify no missing IDs

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Building plan is immutable. Compilers can run independently/parallel from the same plan revision and publish separate representation artifacts.

======================================================================
ERROR HANDLING
======================================================================
Compiler failure never mutates BuildingPlan. Return typed errors/ValidationReport and keep prior valid representation if rebuilding.

======================================================================
DETERMINISM RULES
======================================================================
Compiler output identity derives from plan fingerprint + compiler version/options. Job completion order never changes content.

======================================================================
PERFORMANCE RULES
======================================================================
Batch/merge geometry and queries; cache compiler products by plan hash; avoid one object per architectural micro-feature.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
One native batch pipeline serves all production generation. Reference adapters
are test-only and cannot select alternate algorithms.
