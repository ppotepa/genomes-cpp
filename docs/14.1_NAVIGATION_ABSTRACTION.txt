======================================================================
PUBLIC CONTRACTS
======================================================================
1. AgentProfileId references radius, height, maxStep, maxSlope, movement capabilities and area costs. Profiles are data/versioned; no Infantry enum in core.

2. PathRequest has start/end WorldPosition, agent profile, flags/cost policy, max nodes/time budget, request ID and optional high-level corridor.

3. PathResult has status, polyline/corridor, visited/diagnostic metrics, source nav revision. Partial paths are explicitly marked.

4. NavTileHandle is generational runtime handle; semantic tile key derives from RegionCoord + local tile coord + AgentProfile/nav config version.

======================================================================
DATA LAYOUT
======================================================================
Public nav handles/paths are Genomes types. Recast/Detour pointers and poly refs remain backend-private mappings.

======================================================================
PSEUDOCODE
======================================================================
REQUEST:
    validate profile/start/end
    identify start/end regions
    if required nav tiles unavailable:
        return Unloaded or schedule/load policy
    ticket := nav.submit(request)
    later result := ticket.poll/wait

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
NavigationWorld tile mutation owned by nav service; path queries use immutable/safe snapshots or backend query objects per job.

======================================================================
ERROR HANDLING
======================================================================
Path requests return typed status Success/Partial/NoPath/Unloaded/Cancelled/Invalid and never fabricate a route through unknown regions.

======================================================================
DETERMINISM RULES
======================================================================
Request IDs/stable costs explicit; no semantic order from completion time.

======================================================================
PERFORMANCE RULES
======================================================================
Query scratch/pools reused; no global lock around all path requests.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Native navigation is largely new capability; SOURCE movement/reference behavior is
preserved where tests exist but inefficient absence of global nav is not parity.
