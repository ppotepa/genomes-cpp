CHAPTER 1.3 - EXECUTABLE TARGETS AND TEST RUNNER
STATUS: READY
VERSION: 0.1

======================================================================
GOAL
======================================================================

Standardize native executable targets and the unit/integration test runner so
later chapters never invent incompatible harnesses.

After this chapter:

    - Catch2 v3 is the standard native test framework,
    - Google Benchmark is the standard microbenchmark framework,
    - native tests are grouped by layer,
    - CTest is the single top-level test entry point,
    - apps/headless and future apps share one target convention,
    - benchmarks are never confused with correctness tests.

At the time this chapter was authored, current package/release metadata shows
Catch2 3.x and Google Benchmark 1.9.x as current stable families. Implementation
must pin exact upstream revisions under the Chapter 1.2 policy.

IMPLEMENTATION STEPS
======================================================================

STEP 1
    Verify 1.1 and 1.2 clean build.

STEP 2
    Add Catch2 and google/benchmark using exact pinned submodules under
    Chapter 1.2 policy.

STEP 3
    Update docs/THIRD_PARTY_NATIVE.txt with source/SHA/version/license.

STEP 4
    Configure Catch2:
        build tests/examples/docs OFF where upstream supports it.
        expose Catch2::Catch2WithMain to project tests.
        do not compile Catch2 with project warnings-as-errors.

STEP 5
    Configure Google Benchmark:
        BENCHMARK_ENABLE_TESTING OFF
        BENCHMARK_ENABLE_GTEST_TESTS OFF where applicable.
        use benchmark::benchmark.

STEP 6
    Create GenomesTesting.cmake.

Required helper concept:

    genomes_add_test(
        NAME <logical>
        TARGET <target>
        SOURCES <...>
        LIBRARIES <...>
        LABELS <...>
    )

It:
        creates executable,
        links Catch2::Catch2WithMain,
        links passed Genomes libraries,
        applies project warnings,
        registers tests using Catch2 CMake discovery where practical.

STEP 7
    Migrate 1.1 ad-hoc smoke assertions to Catch2.

Do not lose the bootstrap checks.

STEP 8
    Organize tests/native by subsystem folders as they grow.

Tests should include public headers first.
Implementation-private includes only for explicitly white-box tests.

STEP 9
    Create GenomesBenchmarking.cmake.

Helper concept:

    genomes_add_benchmark(
        NAME <logical>
        TARGET <target>
        SOURCES <...>
        LIBRARIES <...>
    )

It:
        creates executable,
        links benchmark::benchmark,
        applies project warnings.

It does NOT register benchmarks as CTest correctness tests.

STEP 10
    Add one trivial bootstrap benchmark only to validate framework wiring:

        benchmark buildInfo() retrieval

The result has no performance gate and must be marked infrastructure-only.

STEP 11
    Define test labels:

        unit
        integration
        determinism
        parity
        smoke
        stress

Later tests may have multiple labels.

STEP 12
    Define commands:

        ctest --preset dev-debug
        ctest --test-dir ... -L unit
        ctest --test-dir ... -L determinism

STEP 13
    Verify Catch2 listing and CTest discovery.

STEP 14
    Run current legacy core sanity.

======================================================================
PSEUDOCODE
======================================================================

TEST HELPER:

    function genomes_add_test(args):
        require args.TARGET
        require args.SOURCES not empty

        add_executable(args.TARGET, args.SOURCES)

        link(
            args.TARGET,
            Catch2WithMain,
            args.LIBRARIES
        )

        applyGenomesWarnings(args.TARGET)

        discoverCatchTests(
            target = args.TARGET,
            labels = args.LABELS
        )


BENCHMARK HELPER:

    function genomes_add_benchmark(args):
        add_executable(args.TARGET, args.SOURCES)

        link(
            args.TARGET,
            benchmark,
            args.LIBRARIES
        )

        applyGenomesWarnings(args.TARGET)


FOUNDATION TEST:

    TEST_CASE("BuildInfo identifies native bootstrap"):
        info := buildInfo()

        REQUIRE(info.projectName == "Genomes")
        REQUIRE(info.nativeBootstrapVersion == "0.1")

======================================================================
THREADING / OWNERSHIP RULES
======================================================================

Test framework does not define engine threading.

Parallel test execution:
    allowed only when tests are isolated and CTest configuration explicitly
    permits it.

Determinism tests must control thread count themselves.

Benchmarks must report worker/thread configuration.

======================================================================
ERROR HANDLING
======================================================================

Framework discovery failure:
    configure error with dependency remediation.

Correctness assertion:
    Catch2 failure.

Benchmark result:
    never interpreted as correctness pass/fail by default.

======================================================================
DETERMINISM RULES
======================================================================

Tests must never rely on execution order across separate CTest processes.

Seeded tests print/report seed on failure.

Future fuzz/property tests must make failing seeds reproducible.

======================================================================
PERFORMANCE RULES
======================================================================

Correctness tests:
    optimize for precision and diagnostics, not timing.

Benchmarks:
    Release/optimized configuration required for performance conclusions.
    Debug benchmark may be used only for wiring/sanity.

Follow 0.4 for:
    warmup,
    repetitions,
    percentiles,
    thread scaling,
    machine metadata.
