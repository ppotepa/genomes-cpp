======================================================================
PUBLIC CONTRACTS
======================================================================
1. Fixture matrix includes settlement scales, morphologies, terrain/plannedness
extremes, hydrology none/adjacent/through, multiple seeds and at least one
pathological SOURCE regression seed.

Road/parcel fixtures additionally cover:
    SOURCE road-graph-lab MOTORWAY/TRUNK/ARTERIAL/COLLECTOR/LOCAL/SERVICE/PATH
    SOURCE city trunk/arterial/collector/local/alley mapping
    routed curved/smoothed centerlines
    edge splits on curved/polyline roads
    exact shared-node endpoint equality
    SOURCE simple-settlement driveway access semantics:
        Service/Local native class mapping + Track surface/kind
    fenced parcel GateSpec and wood/wire/wall FenceLayout
    FenceGenerator.plan compatibility cases.

2. Fixtures contain normalized TARGET inputs and expected invariants: graph
connectivity, legal crossings, region depth ranges, block/parcel containment,
overlap limits, access feasibility and deterministic identity. Prototype counts
or coordinates are diagnostic observations, not expected TARGET values.

3. Road geometry is accepted by TARGET constraints and quality metrics. A
difference from a prototype needs no compatibility branch or divergence waiver.

4. Fixture provenance pins exact private SOURCE commit; fixture data contains no wholesale SOURCE code.

5. SOURCE procedural-city building records (x/z/w/d/h/rotation/zone/parcel)
are reference placement envelopes and map to BuildingSiteRequest fields only.
They are not BuildingPlan fixtures and their displayed boxes are not required
to match final generated building geometry.

======================================================================
DATA LAYOUT

Graphs use contiguous node/edge arrays with stable IDs and adjacency ranges; fields are grid/raster artifacts; polygons use engine geometry types.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Build SOURCE exporter using existing headless generation hook; add road-graph export hook in temporary/source tooling if needed without moving source to TARGET.

STEP 2
    Normalize graphs by stable canonical ordering and quantize comparison-only coordinates with declared tolerance, while retaining raw numeric fixture where needed.

STEP 3
    Export at least 50 deterministic seeds distributed across profiles plus targeted edge cases.

    Export prototype building placeholders as site-request evidence with an
    explicit REFERENCE_PROTOTYPE classification, never as final building plans.

STEP 4
    Implement the TARGET fixture loader and invariant/quality validators.

STEP 5
    Generate report listing Pass/Regression per TARGET invariant and quality metric.

STEP 6
    Block completion while any required TARGET invariant or scenario is unmapped.
