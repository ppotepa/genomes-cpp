======================================================================
PUBLIC CONTRACTS
======================================================================
1. Destruction domain owns semantic debris/rubble; PhysicsWorld owns body/collider handles. Adapter maps between them; domain structs never expose Jolt types.

2. HERO body creation uses convex/compound simplified collision recipes compiled from semantic debris. Failure emits fallback command to CHEAP/BAKED.

3. Rubble dirty tiles compile one conservative/static collider representation per tile or bounded subpieces. Exact backend shape may differ from SOURCE Rapier heightfield/trimesh/cuboid fallback.

4. Replacement transaction order: create/update replacement collider -> sync/commit physics -> remove superseded dynamic bodies/colliders.

5. Physics contacts emit semantic events; they do not directly mutate structural/render state.

======================================================================
DATA LAYOUT
======================================================================
Adapter keeps maps DebrisId->PhysicsBodyHandle and RubbleTileId->PhysicsShape/BodyHandle. Maps are backend-neutral handles and updated only at sync points.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement debris collision recipe compiler from semantic faces/bounds with bounded convex complexity.

STEP 2
    Queue HERO create/update/remove via PhysicsCommandBuffer; never call backend from arbitrary damage worker.

STEP 3
    Apply impact target impulse/torque exactly once using ImpactResult command.

STEP 4
    Compile dirty rubble tile height/surface to Jolt static shape recipe; choose supported heightfield/mesh/boxes based on capability and benchmark.

STEP 5
    Implement two-phase settle transaction with physics sync acknowledgment.

STEP 6
    Wire sleeping/settled state from physics snapshot into DebrisLifecycle eligibility without making backend handle the semantic owner.

STEP 7
    Stress test collapse with body budgets and verify no missing collision/material.

======================================================================
PSEUDOCODE
======================================================================
SYNC DEBRIS:
    for cmd in destructionPhysicsCommands stable order:
        switch cmd:
          CreateHero:
            result := physics.enqueueCreate(recipe)
            if result fails:
                lifecycle.enqueueFallback(cmd.debrisId)
          ApplyImpulse:
            physics.enqueueImpulse(handle, J, point)
          BakeTile:
            newHandle := physics.enqueueCreateStatic(tileRecipe)
            pendingReplacement[tile] := newHandle

    physics.flush()

    for replacement in confirmed replacements:
        retire old handles
        lifecycle.confirmBaked(...)

SETTLE ORDER:
    semantic deposit -> compile replacement -> physics flush -> remove HERO -> publish representation change

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Recipe compilation may be parallel per debris/tile. Backend command submission/flush follows PhysicsWorld contract. Handle maps mutate on owning sync thread/phase.

======================================================================
ERROR HANDLING
======================================================================
Backend creation failure triggers semantic fallback if conservation-preserving; replacement collider failure leaves old dynamic/static representation active and tile dirty for retry.

======================================================================
DETERMINISM RULES
======================================================================
Physics trajectories may not be bitwise deterministic across platforms unless backend mode guarantees it; semantic lifecycle decisions based on stable snapshots/ticks and IDs. Parity focuses invariants.

======================================================================
PERFORMANCE RULES
======================================================================
Bound convex vertices/subshapes. Batch dirty tiles and commands. Avoid rebuilding unchanged rubble colliders. Measure active bodies, contacts, rebuild ms.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Rapier implementation is SOURCE reference only. Jolt shape choice may differ while preserving collision/navigation/settle behavior.
