======================================================================
PUBLIC CONTRACTS
======================================================================
1. ProjectilePool uses generational ProjectileHandle and hot SoA columns position/velocity/mass/diameter/state/strategy, with optional cold/contact data handles. Active list compacted without changing stable ProjectileId.

2. Flight/aerodynamic free-space integration is batch-friendly and may SIMD/autovectorize grouped by strategy. Contact-heavy projectiles move to separate slow/contact queues without forcing divergent branches on free-flight batch.

3. Parallel batches read immutable WorldQuery/Physics snapshots for the tick and write disjoint projectile ranges plus thread-local Impact/Blast/Spawn command buffers.

4. After flight batches, commands are merged/stable-sorted by tick/shot/projectile/contact sequence and target semantic ID before damage commit. Fragment spawn resolves stable IDs independently from pool slot allocation.

5. SIMD optimization is optional per compiler/ISA; scalar reference stays in tests. No architecture-specific path becomes sole implementation.

======================================================================
DATA LAYOUT
======================================================================
Hot SoA arrays aligned to cache/SIMD boundaries. FreeFlight index list, Contact index list and terminal/free slot lists. Strategy-group index lists may be rebuilt incrementally. Cold trace history not stored in hot pool.

======================================================================
PSEUDOCODE
======================================================================
TICK:
    active := pool.activeIndices
    parallelFor(active batches):
        for idx:
            if projectile.contactActive:
                local.contactQueue.push(idx)
            else:
                integrate aerodynamic/free flight
                if broadphase predicts candidate:
                    local.contactQueue.push(idx)
                else write state

    contactJobs := partition gathered contact indices
    solve contacts -> local commands

    commands := stableMerge(all job buffers)
    commit target damage/blast
    commit fragment spawns
    retire terminal projectiles

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Each projectile index written by one job per phase. Shared target state immutable until command commit. Pool structural create/destroy happens after batches.

======================================================================
ERROR HANDLING
======================================================================
Pool exhaustion follows profile policy: reject new noncritical projectile or account HE omitted pairs explicitly; never overwrite active state. Invalid SIMD path detected by scalar parity tests.

======================================================================
DETERMINISM RULES
======================================================================
Projectile results match scalar reference within exact/numeric policy at 1/N workers. Command order stable independent of pool index/job completion.

======================================================================
PERFORMANCE RULES
======================================================================
Measure scheduler overhead, spatial query %, contact solver %, memory bandwidth, vectorization. Avoid SIMD effort on highly divergent contact solver until profiling proves benefit.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Replaces JS single-loop projectile stepping with native data-oriented batches while preserving parity.
