======================================================================
PUBLIC CONTRACTS
======================================================================
1. NavBuildConfig explicitly records cellSize, cellHeight, tileSize, agent profile dimensions, region/contour/poly detail parameters and partition mode; config fingerprint is part of tile artifact key.

2. Recast pipeline: rasterize source geometry -> filter -> compact heightfield
-> regions -> contours -> poly mesh -> detail -> Detour tile data.

At the audited upstream baseline the root project reports LIB_VERSION 1.6.0
and CMake options RECASTNAVIGATION_DEMO/TESTS/EXAMPLES. The exact Git SHA
remains authoritative; do not code against an assumed package-manager version.

3. Detour runtime is tiled; dtNavMesh/dtNavMeshQuery remain backend-private.
Query objects are pooled/per-thread because mutable query scratch is not shared
blindly.

The 32-bit vs 64-bit dtPolyRef choice
(RECASTNAVIGATION_DT_POLYREF64 in the current upstream CMake) must be decided
before native save/nav artifact schemas are frozen. Public Genomes NavPolyHandle
must not expose dtPolyRef width.

4. World global double coordinates convert to local nav origin float coordinates per region/nav world to maintain precision.

======================================================================
DATA LAYOUT
======================================================================
Public nav handles/paths are Genomes types. Recast/Detour pointers and poly refs remain backend-private mappings.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define default profile/config from gameplay-scale requirements but keep values data-driven and benchmarkable.

STEP 2
    Build one synthetic tile from terrain/building recipe triangles and add to dtNavMesh.

STEP 3
    Create query pool sized to JobSystem concurrency; each active query gets exclusive dtNavMeshQuery.

STEP 4
    Implement nearest poly, findPath corridor, findStraightPath polyline, nav raycast and area cost filter conversion.

STEP 5
    Implement tile add/remove preserving desired refs when reload possible, while public tile handles remain Genomes-owned.

STEP 6
    Test stair/off-mesh connection recipe from BuildingNavCompiler.

======================================================================
PSEUDOCODE
======================================================================
BUILD TILE:
    rasterize triangles into rcHeightfield
    filter walkable
    build compact heightfield
    partition regions
    trace contours
    build poly mesh + detail
    dtCreateNavMeshData
    return NavTileArtifact bytes

QUERY:
    q := queryPool.acquire()
    startRef := nearestPoly(start)
    endRef := nearestPoly(end)
    refs := q.findPath(startRef,endRef,filter)
    points := q.findStraightPath(...)
    release q

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Tile builds parallel per independent tile using job-local Recast contexts/allocations. dtNavMesh mutation serialized/staged; queries use exclusive query objects.

======================================================================
ERROR HANDLING
======================================================================
Path requests return typed status Success/Partial/NoPath/Unloaded/Cancelled/Invalid and never fabricate a route through unknown regions.

======================================================================
DETERMINISM RULES
======================================================================
Tile geometry/config/source revision determine artifact. Recast floating details may be platform-sensitive; fixture tolerances and artifact platform/version policy explicit.

======================================================================
PERFORMANCE RULES
======================================================================
Tiled build, pooled query objects, no full-world rebuild, benchmark tile time/path throughput.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Native navigation is largely new capability; SOURCE movement/reference behavior is
preserved where tests exist but inefficient absence of global nav is not parity.
