======================================================================
PUBLIC CONTRACTS
======================================================================
1. PhysicsBodyHandle/ShapeHandle are generational Genomes handles. Public BodyDesc contains motion type Static/Kinematic/Dynamic, transform, mass/density policy, damping, gravity factor, collision layer, motion quality and user semantic ID.

2. ShapeRecipe variants: Sphere, Box, Capsule, Cylinder, ConvexHull, TriangleMesh, HeightField, Compound. Backend unsupported recipes return typed Unsupported or are precompiled into supported form by owning compiler.

3. PhysicsWorld mutations are command-buffered. Public API does not permit arbitrary body mutation while backend step is running.

4. ContactEvent is copied into Genomes event buffer with body handles/semantic IDs, point, normal, relative velocity/impulse metadata; domain code never holds backend contact pointers.

======================================================================
DATA LAYOUT
======================================================================
Public physics handles/recipes are Genomes-owned. Jolt BodyID/ShapeRef are backend-private mappings.

PSEUDOCODE
======================================================================
STEP:
    applyCommands(preStep)
    backend.beginStep()
    backend.update(fixedDt)
    events := drainBackendCallbacks()
    backend.endStep()
    applyCommands(postStepAllowed)
    snapshot := extractChangedBodies()
    publish events + snapshot

COMMAND:
    producer threads -> local command buffers
    merge stable by phase/sequence where semantic ordering matters
    physics owner applies

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
PhysicsWorld has one stepping owner. Producers can build command buffers in jobs. Queries during step follow backend-supported read rules; default Genomes policy schedules gameplay queries outside active Update.

======================================================================
ERROR HANDLING
======================================================================
Backend errors map to typed PhysicsError/diagnostics. Failed body creation or step does not leave half-registered public handles.

======================================================================
DETERMINISM RULES
======================================================================
Command semantic order is stable for conflicting operations on same body; independent operations may execute backend-defined order.

======================================================================
PERFORMANCE RULES
======================================================================
Commands batched; shape recipes cached; query collectors caller-owned scratch.
