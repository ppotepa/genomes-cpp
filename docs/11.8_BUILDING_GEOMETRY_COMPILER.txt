======================================================================
PUBLIC CONTRACTS
======================================================================
1. Compiler emits render meshes grouped by material/representation chunk, plus mapping ranges from triangles/vertices to StructuralElementId where needed for picking/damage visualization.

2. Far representation may be simple envelope/roof proxy; World/detail representation contains openings/interiors according render profile. LOD changes representation only, not BuildingPlan identity.

3. Windows/doors can be geometry or material/instance submeshes but openings in
wall geometry must match semantic openings. The same semantic opening state
must drive the collision compiler; a visually open door/window with a solid
collision wall, or vice versa, is a correctness failure.

SOURCE BuildingWorldRepresentation and BuildingCollisionProxy both derive their
wall solids from BuildingPlan openings; TARGET preserves this single-source
relationship.

4. Normals/tangents/UVs generated deterministically with seam policy; no duplicate micro-object per brick/window frame by default.

======================================================================
DATA LAYOUT
======================================================================
Semantic plan arrays remain renderer/physics/nav independent. Compiler products are versioned artifacts keyed by BuildingPlan fingerprint.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement wall panel meshing with rectangular/polygon openings via robust triangulation backend.

STEP 2
    Compile slabs/floors/ceilings, roof surfaces, stairs/rails at selected detail.

STEP 3
    Generate material-slot grouped MeshData and semantic range mapping.

STEP 4
    Implement FAR envelope compiler separately, using footprint/storeys/roof outline.

STEP 5
    Generate bounds and shared/reused primitive meshes for repeatable details where possible.

STEP 6
    Benchmark building batch compile and mesh memory; cache by plan/compiler hash.

======================================================================
PSEUDOCODE
======================================================================
COMPILE WALL:
    facePolygon := wall rectangle in local 2D
    holes := semantic openings projected to face
    triangles := triangulate(facePolygon,holes)
    extrude thickness / emit front/back/reveals according detail
    append semanticMapping(triangleRange, structuralElementId)

LOD:
    if FAR:
        compile envelope + roof
    else:
        compile structural surfaces + openings + selected detail

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Building plan is immutable. Compilers can run independently/parallel from the same plan revision and publish separate representation artifacts.

======================================================================
ERROR HANDLING
======================================================================
Compiler failure never mutates BuildingPlan. Return typed errors/ValidationReport and keep prior valid representation if rebuilding.

======================================================================
DETERMINISM RULES
======================================================================
Compiler output identity derives from plan fingerprint + compiler version/options. Job completion order never changes content.

======================================================================
PERFORMANCE RULES
======================================================================
Batch/merge geometry and queries; cache compiler products by plan hash; avoid one object per architectural micro-feature.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET BuildingPlan and compiler validators define behavior; no renderer or
physics reference implementation selects a production path.
