CHAPTER 11.7 - STRUCTURAL_AND_MATERIAL_MODEL
STATUS: READY

======================================================================
GOAL
======================================================================
Derive generic structural/material topology from BuildingPlan so destruction, collision and rendering share semantic wall/slab/roof/foundation elements without making any one representation authoritative.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. StructuralElement types include Foundation, Slab, ExteriorWall, InteriorWall, PartyWall, Column/Beam optional, RoofSurface/Support. Every element has stable StructuralElementId, geometry span/profile, material class, thickness, storey, openings and connectivity/support references.

2. Material is semantic construction material/profile (wood, brick, masonry, concrete, steel, glass, roof covering etc.) with physical/destruction parameters referenced by MaterialId; final calibrated values owned by destruction/material chapter.

3. Structural graph records support/load-path adjacency sufficient for later damage propagation; this chapter does not implement finite element analysis.

4. Wall elements are segmented by meaningful topology/opening boundaries, not every render triangle.

======================================================================
DATA LAYOUT
======================================================================
Semantic plan arrays remain renderer/physics/nav independent. Compiler products are versioned artifacts keyed by BuildingPlan fingerprint.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Convert room/exterior wall topology to centerline/plane wall elements and apply thickness/profile.

STEP 2
    Subtract semantic openings from panel records as hole intervals/polygons rather than destructively triangulating plan.

STEP 3
    Create slabs with stair/core openings and roof support surfaces.

STEP 4
    Create support graph: slab->walls/columns/foundation, roof->supports, wall vertical alignment across storeys where applicable.

STEP 5
    Assign material profiles from BuildingSpec/program/seed using deterministic substreams.

STEP 6
    Validate no orphan load-bearing element, thickness positive, opening contained.

======================================================================
PSEUDOCODE
======================================================================
FOR wall run:
    segments := split at corners, T junctions, material/storey changes
    for segment:
        element := StructuralWall(id, plane, thickness, material)
        element.openings := openings intersecting run
        graph.add(element)

SUPPORT GRAPH:
    for element:
        candidates := spatial/support relation below
        add directed support edges
    validate each load-bearing nonfoundation has path to foundation

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Building plan is immutable. Compilers can run independently/parallel from the same plan revision and publish separate representation artifacts.

======================================================================
ERROR HANDLING
======================================================================
Compiler failure never mutates BuildingPlan. Return typed errors/ValidationReport and keep prior valid representation if rebuilding.

======================================================================
DETERMINISM RULES
======================================================================
Compiler output identity derives from plan fingerprint + compiler version/options. Job completion order never changes content.

======================================================================
PERFORMANCE RULES
======================================================================
Batch/merge geometry and queries; cache compiler products by plan hash; avoid one object per architectural micro-feature.

MIGRATION / COMPATIBILITY
