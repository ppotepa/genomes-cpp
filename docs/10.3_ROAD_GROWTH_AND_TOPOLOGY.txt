======================================================================
PUBLIC CONTRACTS
======================================================================
1. Growth work item/Bud has stable ID, origin node, direction, class, energy/depth, parent road, generation epoch and SeedPath.

2. Candidate segment undergoes hard checks in fixed order: world/region bounds, water/class, length/slope, nearest snap, crossing broadphase+robust intersection, duplicate/angle constraints.

3. Proper intersection splits existing edge before connecting. Endpoint snap uses explicit snap radius and deterministic nearest tie by distance then stable ID.

4. Growth queue ordering is semantic/stable priority, not worker completion; candidates may be evaluated parallel against immutable graph snapshot then committed in deterministic phase.

======================================================================
DATA LAYOUT
======================================================================
Graphs use contiguous node/edge arrays with stable IDs and adjacency ranges; fields are grid/raster artifacts; polygons use engine geometry types.

PSEUDOCODE
======================================================================
EVALUATE BUD:
    dir := growthField.direction(bud.position,bud.seed)
    endpoint := propose length/turn
    candidate := Segment(start,endpoint)
    if hard constraint fails: reject(reason)
    snap := nearest eligible node/edge
    crossings := roadIndex.query(candidate.bounds)
    classify robust intersections
    return Proposal(budId,candidate,snap,crossings,score)

COMMIT BATCH:
    stableSort proposals by ProposalKey
    for p:
        revalidate against current graph
        if proper crossing: split target edge
        add/snap edge
        spawn child buds with semantic child seeds

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
