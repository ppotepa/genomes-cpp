======================================================================
PUBLIC CONTRACTS
======================================================================
1. GPU culling input: instance bounds, transform, mesh/LOD table, camera/frustum, optional previous visibility. Output compact visible instance/draw command buffers plus counters.

2. LOD uses projected error/screen size + hysteresis, not only arbitrary distance; domain identity/random seed never changes on LOD transition.

3. Frustum cull first; optional Hi-Z occlusion added only after depth pyramid path exists. CPU reference computes same frustum/LOD policy for tests.

4. Indirect draw support is capability-gated; fallback groups visible instances on CPU without changing visual correctness.

======================================================================
PSEUDOCODE
======================================================================
KERNEL each instance:
    if !frustumIntersects(boundsWorld): return
    lod := chooseLod(projectedError, previousLod, hysteresis)
    if occlusionEnabled and occludedByHiZ: return
    idx := atomicAdd(visibleCount[lodGroup],1)
    visibleIndices[groupBase+idx] := instanceId

DRAW:
    build commands from group counts
    execute indirect where capability


======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.

======================================================================
MIGRATION / COMPATIBILITY
