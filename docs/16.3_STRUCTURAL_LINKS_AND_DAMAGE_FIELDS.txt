======================================================================
PUBLIC CONTRACTS
======================================================================
1. DamageField is defined in stable local material coordinates, not render vertices. Cell resolution/bounds are explicit and versioned.

2. Damage channels/holes store centerline/radius/depth/removedVolume and deterministic IDs. Aggregate part.damage is diagnostic derived state, never the sole damage truth.

3. StructuralGraph nodes represent semantic structural parts; edges represent supports/connections with capacity/state. Render mesh groups are not structural nodes by default.

4. Damage events update local fields first; support weakening is derived from affected semantic region/material and emits StructuralStateChange commands.

5. Detachment occurs when graph/support policy marks a component unsupported/failed.

======================================================================
DATA LAYOUT
======================================================================
DamageField uses bounded dense or sparse cell tiles chosen by chapter constants; cells store compact floats/quantized fields after benchmark. StructuralGraph uses contiguous node/edge arrays with stable IDs and adjacency offsets.

======================================================================
PSEUDOCODE
======================================================================
APPLY DAMAGE:
    bounds := cellsOverlapping(localPoint, radius)
    for cell in stableIndexOrder(bounds):
        d := distance(cell.center, localPoint)
        if d > radius: continue
        w := falloff(d/radius)
        cell.crush += energy * w * coeff.crush
        cell.crack += energy * w * coeff.crack
        cell.weakness := clamp(cell.weakness + ..., 0, 1)

SUPPORT:
    supported := flood/DFS from anchor nodes over edges where edge.capacityRemaining > 0
    for structural node in stableIdOrder:
        if node was supported and now !supported:
            commands.push(DetachComponent(node.componentId))

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Damage updates to one field require exclusive owned tile/range or command reduction. Different structures can update in parallel. Support graph evaluation reads committed damage state and writes local result buffers.

======================================================================
ERROR HANDLING
======================================================================
Out-of-bounds damage is clipped/reported according to command contract. Invalid topology (dangling edge, duplicate ID) rejected at compile/validation time.

======================================================================
DETERMINISM RULES
======================================================================
Cell iteration and graph traversal use stable index order. Floating accumulation for multiple same-tick impacts uses deterministic command sort/reduction policy from 15.4.

======================================================================
PERFORMANCE RULES
======================================================================
Damage cost proportional to affected cells, never whole building mesh. Support evaluation should operate on compact graph; dirty-component incremental evaluation may be added after correctness benchmark.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Building-specific panels adapt into generic structural graph. Preserve lazy damage representation and existing tests as invariant/behavioral evidence.
