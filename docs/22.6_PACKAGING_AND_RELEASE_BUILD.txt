======================================================================
PUBLIC CONTRACTS
======================================================================
1. Release package is produced from exact Git commit + recursive dependency SHAs using documented toolchain/preset. Package manifest records build version, commit, dependency pins, shader/artifact versions.

2. Ship only required runtime binaries/resources/licenses; no private SOURCE repository, test fixtures requiring privacy, compiler caches or developer absolute paths.

3. Precompile/package shaders/pipelines/assets where tooling supports, with runtime cache version invalidation. Keep source shader inclusion policy explicit.

4. Release configuration disables expensive debug visualization/validation by default but retains diagnostics/error handling needed for recovery; assertions policy follows 0.3.

5. Headless package build remains available independently where useful for tests/server/simulation tooling.

6. Release acceptance requires correctness/parity, memory, thread/GPU regression gates and clean-package launch from fresh directory.

======================================================================

Package manifest JSON/text: app version, target commit, dependency SHAs/licenses, platform/arch, build config, schema/generator versions, file hashes.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define CMake install components: runtime, tools optional, headless optional, licenses, shaders/assets/config.

STEP 2
    Generate THIRD_PARTY_NOTICES from recorded dependency metadata and include license files.

STEP 3
    Implement build/package manifest generation without __DATE__/__TIME__ semantic nondeterminism; release build timestamp may be metadata only if desired.

STEP 4
    Compile/package shader artifacts and validate RenderState/Pipeline cache compatibility/version; first-run cache writable location separate from install.

STEP 5
    Strip tests/benchmarks/reference goldens from shipping package unless explicitly tool build.

STEP 6
    Create native-release CI workflow: clean recursive checkout, release configure/build/test, package, unpack to new directory, run headless/game smoke, verify manifests/licenses.

STEP 7
    Run production acceptance: determinism/parity suite, controlled perf gates, memory/leak loops, corrupted-cache recovery and no SOURCE access.

STEP 8
    Document release checklist and rollback/version upgrade procedure.

======================================================================
PSEUDOCODE
======================================================================
RELEASE PIPELINE:
    checkout exact commit recursive submodules
    verify clean tree + dependency pins
    configure release preset
    build
    run required correctness/parity tests
    run/verify dedicated regression gates
    cmake --install to staging
    generate package manifest + file hashes + notices
    archive staging
    unpack archive to clean temp
    run headless --self-test
    run game smoke with packaged assets/shaders
    verify no SOURCE/private path dependency
    publish artifact only if all pass

MANIFEST:
    targetCommit
    dependencyShas
    platform/arch
    schema/generator versions
    package file hashes

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Packaging tools deterministic/reentrant; runtime thread behavior already gated. Release workflow parallel compile is irrelevant to runtime semantics.

======================================================================
ERROR HANDLING
======================================================================
Any missing license/resource/shader/version mismatch/package smoke failure blocks release. No "warn and ship" for required content.

======================================================================
DETERMINISM RULES
======================================================================
Build artifacts may differ due compiler/link metadata unless reproducible-build policy later tightens; gameplay semantic versions/seeds unaffected. Package manifest explicit.

======================================================================
PERFORMANCE RULES
======================================================================
Release uses same optimization/LTO policy as benchmark baseline or documents difference and reruns gates. Do not benchmark Debug then ship different untested flags.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
SOURCE is not a package dependency. Reference fixtures remain development repository artifacts.
