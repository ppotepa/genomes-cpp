SEAM
 Tylko engine/render/threepp/ThreeppGlBootstrap.cpp dostaje prywatny
 include src/ oraz src/external/glad. Nie kompilujemy drugiego glad.c.
 Pierwsza inicjalizacja: threepp::loadGlad(resolver SDL).
 Następny kontekst w tym samym procesie: odświeżenie TEJ SAMEJ tablicy
 przez gladLoadGLLoader. Samo loadGlad ponownie nic by nie zrobiło,
 a zamknięcie ostatniego okna może rozładować sterownik.
 Brak równoległych kontekstów. Wywołania na wątku SDL/main.

SDL3 resolver zwraca wskaźnik funkcji, GLAD1 oczekuje void*.
Izolowane reinterpret_cast ma kontrakt desktop Windows/Linux GL ABI.
Nie rozszerzać tego założenia na inne platformy bez odrębnego odbioru.

CMAKE
 Minimalne CMake 3.21; schema presetów 3 odpowiada temu minimum.
 GLFW/editor/examples/tests/audio/Vulkan/Python/FBX/USD/RLTOOLS/
 FSR/DLSS/inference wyłączone zmiennymi w zakresie funkcji.
 BUILD_SHARED_LIBS=OFF tylko w zakresie konfiguracji threepp:
 upstream src/CMakeLists.txt linkuje glfw przy BUILD_SHARED_LIBS=ON
 nawet bez frontendu GLFW. Nie zmieniać na shared bez nowego audytu.
 EXCLUDE_FROM_ALL nie oznacza, że CMake nie deklaruje żadnego
 opcjonalnego targetu (np. wykrytego V-HACD); nie linkujemy go do gry.
 Headless nie wchodzi w konfigurację threepp ani nie wymaga jego checkoutu.
 Pin sprawdzany przez git rev-parse i tracked diff; nie ma autoupgrade.
