======================================================================
PUBLIC CONTRACTS
======================================================================
1. FootprintCandidate may use occupancy grid as solver representation but final output is Polygon2/FootprintCells plus transformation/grid metadata.

2. Hard constraints: inside buildable polygon/parcel, connected, no unintended hole, min dimensions, aspect/occupancy/area envelopes, road/setback constraints already encoded by buildable input.

3. Operations include base rectangle, wing add, corner/recess carve and symmetric paired operations with bounded retry/budget.

4. Symmetry and regularity are generation priors/objectives, not post-hoc labels.

======================================================================

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Normalize buildable polygon to solver local grid with configurable cell size and raster containment conservative policy.

STEP 2
    Create base rectangle near target cells and aspect from semantic RNG.

STEP 3
    Apply bounded operation budget derived from complexity/regularity; each proposal validates immediately.

STEP 4
    Paired symmetric operations mirror across chosen symmetry axis.

STEP 5
    Convert accepted cell boundary to normalized polygon; simplify only under topology-preserving tolerance.

STEP 6
    Validate polygon inside buildable and area/occupancy metrics; emit trace history.

======================================================================
PSEUDOCODE
======================================================================
GENERATE:
    targetCells := targetArea/(grid*grid)
    cells := baseRectangle(targetCells, seededAspect)
    for opIndex in [0,opBudget):
        for attempt in [0,maxAttempts):
            op := choose wing/recess/paired using child seed(opIndex,attempt)
            candidate := apply(cells,op)
            if validate(candidate,spec):
                cells := candidate
                trace.accept
                break
            trace.reject
    polygon := boundary(cells)
    validate final
    return footprint

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
One BuildingPlan candidate is owned by one job until frozen. Batch jobs are independent by BuildingId/SeedPath and merge in stable ID order.

======================================================================
ERROR HANDLING
======================================================================
Bounded solvers return typed failure/fallback reasons and ValidationReport. Invalid building candidates are never partially committed.

======================================================================
DETERMINISM RULES
======================================================================
Candidate order, tie-breaking and RNG streams are stable by semantic IDs. Worker count and hash-map iteration do not affect the plan.

======================================================================
PERFORMANCE RULES
======================================================================
Use bounded candidate sets, spatial/prefix structures and scratch arenas. No unbounded backtracking. Batch independent buildings over JobSystem.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET constraints and quality metrics define behavior. Prototypes contribute
scenarios only and cannot select alternate solver algorithms.
