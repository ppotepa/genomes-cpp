======================================================================
PUBLIC CONTRACTS
======================================================================
1. BVH build consumes primitives with AABB + stable primitive ID; stored leaves reference IDs/ranges, not domain pointers.

2. Initial build uses binned SAH or median fallback with deterministic tie-breaking. Node array is flat contiguous.

3. Ray/segment/AABB query returns candidate IDs; domain narrow phase is separate unless triangle primitive backend explicitly used.

4. SpatialQuery service combines static BVH + dynamic grid sources and labels source/type; it does not own domain objects.

======================================================================
DATA LAYOUT

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement Aabb3 and slab ray/AABB robust zero-direction handling if not in math layer.

STEP 2
    Build flat BVH recursively/iteratively; choose binned SAH with stable ID tie break, median for tiny partitions.

STEP 3
    Store child indices/leaf range in 32-bit fields where limits allow; assert build limits.

STEP 4
    Implement stack-based ray query using caller scratch stack; near child first for ray.

STEP 5
    Implement AABB overlap query.

STEP 6
    Add SpatialQuery facade that merges static/dynamic candidate sets without semantic sorting unless caller requests stable order.

STEP 7
    Benchmark build time, memory, 10k rays vs brute force.

PSEUDOCODE
======================================================================
BUILD(range):
    bounds := union all
    if count <= leafThreshold: emit leaf
    split := chooseSAH(range)
    if invalid split: stableMedianSplit
    node.left := BUILD(left)
    node.right := BUILD(right)

RAY QUERY:
    stack.push(root)
    while stack:
        node := pop
        if !rayAabb(node.bounds): continue
        if leaf: append primitive IDs
        else push children near-first
