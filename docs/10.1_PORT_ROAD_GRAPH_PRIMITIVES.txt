======================================================================
PUBLIC CONTRACTS
======================================================================
1. RoadNode has stable RoadNodeId, exact XZ position + sampled height/ref,
node type and region lineage.

RoadEdge has stable RoadEdgeId, endpoint node IDs, RoadClass, surface,
width/ROW, speed/capacity, bridge/tunnel level, lineage/seed metadata AND an
explicit RoadCenterline.

RoadCenterline supports at minimum:
    StraightSegment
    Polyline
    CubicBezier

SOURCE city currently uses curved/smoothed routed polylines; cubic Bézier is a
supported representation for later procedural roads; straight/polyline forms
remain first-class and are not forcibly converted to Bézier.

HARD GEOMETRIC CONTRACT:
    centerline.startPosition == RoadNode(a).position
    centerline.endPosition   == RoadNode(b).position

These endpoint values are canonical node coordinates, not approximately copied
values. Mesh/ROW/sidewalk geometry must derive from the same centerline, so two
edges sharing a node cannot create a geometric gap because of independent
endpoint sampling.

2. Graph mutation occurs only during candidate generation. Published RoadGraphArtifact is immutable.

3. splitEdge(eid,p) retires original edge in build graph and creates deterministic child IDs derived from parent ID + split ordinal/quantized semantic point key.

4. Adjacency arrays/indices support degree/other/endpoints without per-edge heap sets in published artifact.

5. splitEdge(eid,p) splits BOTH graph topology and RoadCenterline geometry at
one canonical split parameter/point. The new node stores the exact split point;
both child centerlines reuse that exact node coordinate at their shared end.
For Bézier, use a mathematically exact subdivision such as de Casteljau at t.
For polyline, split the intersected segment and insert one canonical point.

6. Published edge bounds and spatial indexes are computed from the complete
centerline/corridor, not only endpoint chord bounds.

======================================================================
PSEUDOCODE
======================================================================
ADD EDGE:
    require a != b
    if adjacency contains same endpoint pair + semantic lane/level key:
        return Existing
    id := deriveEdgeId(seed,parent,lineageOrdinal)
    append edge
    adjacencyBuild[a].push(id)
    adjacencyBuild[b].push(id)

SPLIT:
    old := edge[eid]
    deactivate old
    n := addNode(point, Junction)
    e1 := addEdge(old.a,n,copyMetadata(old), child=0)
    e2 := addEdge(n,old.b,copyMetadata(old), child=1)
    return n,e1,e2

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Each generation stage reads immutable prior artifacts and writes a candidate output; independent regions/blocks/parcels use jobs with stable IDs and stable merge.

======================================================================
ERROR HANDLING
======================================================================
Invalid candidates are rejected through typed result/ValidationReport; bounded fallback strategies are explicit and traced.

======================================================================
DETERMINISM RULES
======================================================================
Stable seed paths, node/edge IDs and deterministic tie-breakers define output; hash-map/job iteration never does.

======================================================================
PERFORMANCE RULES
======================================================================
Use spatial indexes/fields rather than global scans; batch expensive routing/placement and benchmark large city profiles.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET road topology, profiles and validators are authoritative. Prototype
graphs are optional diagnostic scenarios only.
