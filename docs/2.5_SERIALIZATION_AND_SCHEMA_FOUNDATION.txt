======================================================================
PUBLIC CONTRACTS
======================================================================
1. SchemaVersion is {major, minor}. Major incompatible; minor backward-compatible additive only when reader rules explicitly allow it.

2. Canonical binary encoding uses explicit little-endian integers, IEEE-754 bit encoding where floats are allowed, length-prefixed UTF-8 strings, and no raw struct dumps.

3. BinaryReader is bounds-checked and returns Result. Malformed data never causes unchecked pointer arithmetic or allocation based on unbounded length.

4. CanonicalJson is for fixtures/debug interchange, with deterministic object-key ordering and deterministic numeric formatting; production artifact binary format may differ later.

5. Every serialized root includes magic/type id, schema version, payload length and content/checksum field once artifact hashing chapter defines it.

======================================================================
DATA LAYOUT
======================================================================
Use compact value types, explicit ownership, contiguous storage in hot paths, and no hidden shared mutable state.

======================================================================
PSEUDOCODE
======================================================================
WRITE STRING:
    require utf8ValidatedOrPolicyAllowsBytes
    writeU32(length)
    writeBytes(data)

READ STRING:
    n := readU32()
    if n > limits.maxStringBytes: fail SizeLimit
    if remaining < n: fail Truncated
    return viewOrOwnedString(next n bytes)

ROOT:
    write magic
    write typeId
    write schema.major
    write schema.minor
    write payloadLength
    write payload

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
    - Ownership is explicit.
    - Public APIs do not hide global mutable state.
    - Thread safety is documented per type.
    - Cross-thread mutation uses later JobSystem/command-buffer contracts where applicable.

======================================================================
ERROR HANDLING
======================================================================
Expected failures return Result/typed errors. Programmer-contract violations use diagnostics/assertion policy. No exception-driven hot-path control flow.

======================================================================
DETERMINISM RULES
======================================================================
Deterministic output must not depend on pointer values, hash-map iteration order, thread completion order, wall time, or platform-dependent representations.

======================================================================
PERFORMANCE RULES
======================================================================
No hidden per-call heap allocation in hot paths. Add benchmark coverage for performance-sensitive primitives and follow 0.4.
