GOAL
======================================================================
Port the generic destruction material/solid model into native C++ without coupling it to buildings, Infantry, Jolt or rendering. The result is the semantic substrate for impacts, structural damage, rubble and ballistics.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. MaterialId and PhysicalSolidId are strong semantic IDs. Material definition contains density plus explicitly named game-model coefficients; do not label calibration as certified engineering data.

2. MaterialAssembly owns an ordered sequence of Layer{material,start,end,physicalSolidId}. start/end are distances along MaterialFrame.normal from MaterialFrame.origin. void/air layers contribute path/time but zero material resistance.

3. Adjacent technical mesh pieces sharing one physicalSolidId remain one physical interface unless a declared gap separates them.

4. MaterialFrame = origin + orthonormal normal/tangent basis in world/semantic coordinates. Rotation/translation of the assembly must transform the frame equivariantly.

5. MaterialField sampling is deterministic from stable seed/path and local coordinates; sampling result may vary spatially but cannot depend on render tessellation.

======================================================================
DATA LAYOUT
======================================================================
Prefer compact immutable catalogs and contiguous layer arrays. MaterialDefinition is POD-like numeric data. MaterialAssembly stores Span/vector of layers plus transform/frame and bounds; renderer handles are forbidden.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define MaterialId, MaterialDefinition and a versioned MaterialCatalog API. Port current material names/coefficients as gameplay calibration data with source provenance.

STEP 2
    Define MaterialFrame validation: finite vectors, nonzero normal, normalized orthogonal basis within explicit tolerance.

STEP 3
    Define Layer and MaterialAssembly. Validate ordered non-overlapping intervals; allow explicit void/air layers; reject negative thickness.

STEP 4
    Implement world-to-material and material-to-world transforms used by sampling and traversal.

STEP 5
    Implement deterministic material-field sample interface using SeedPath/stable IDs, independent of mesh triangles.

STEP 6
    Translate SOURCE destruction-core fixtures for layered wall, reversed wall, two panes with air gap and shared physicalSolidId technical sections.

STEP 7
    Add serialization-ready version fields but defer binary format to owning schema chapter.

======================================================================
PSEUDOCODE
======================================================================
VALIDATE ASSEMBLY:
    require layers sorted by start
    previousEnd := 0
    for layer in layers:
        require layer.end >= layer.start
        require layer.start >= previousEnd - tolerance
        if layer.start > previousEnd:
            implicitGap := [previousEnd, layer.start] with zero resistance
        previousEnd := layer.end

SAMPLE MATERIAL:
    local := worldToMaterial(frame, worldPoint)
    stream := SeedTree(rootSeed).child("material-field", physicalSolidId)
    return field.sample(local, stream)

INTERFACE GROUP:
    contiguous sections with same physicalSolidId and no real gap
        => one physical contact
    declared air/void or positive gap
        => contact terminates

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Material catalogs are immutable after initialization. Assemblies may be read concurrently. Damage mutation belongs to later command-buffer stages, not this chapter.

======================================================================
ERROR HANDLING
======================================================================
Invalid layer topology returns ValidationReport/Result error with assembly/layer IDs. Missing material ID is NotFound. No silent default material in production path.

======================================================================
DETERMINISM RULES
======================================================================
Catalog ordering and field seeds use stable IDs. Hash-map iteration never defines layer order. Identical input/version/seed yields identical semantic sampling.

======================================================================
PERFORMANCE RULES
======================================================================
Layer traversal is O(L) for small layer counts; no heap allocation per query. Assembly broadphase uses spatial structures from Stage 4, not scans of all solids.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Export selected SOURCE material assemblies into TARGET reference fixtures. Preserve legacy names/calibration; improvements require a versioned material profile rather than rewriting existing fixture expectations.
