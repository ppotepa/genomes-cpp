======================================================================
PUBLIC CONTRACTS
======================================================================
1. NavTileArtifact is semantic build output/cacheable bytes + config/source fingerprints, independent from live dtNavMesh handle.

2. Region navigation residency may differ by AgentProfile; infantry profile loaded while vehicle nav absent is valid.

3. Tile source geometry combines terrain, static building nav recipes, roads/walkable modifiers and explicit off-mesh links for that revision.

4. Streaming commits tile only if region/nav generation token and source revisions still current.

======================================================================

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define tile grid within RegionCoord and overlap border padding sufficient for seam links.

STEP 2
    Generate dirty/build tiles in jobs from immutable region package.

STEP 3
    Cache tile artifacts by geometry/config fingerprint.

STEP 4
    On stream-in stage add tiles to Detour backend and update Region residency/profile revision.

STEP 5
    On unload remove tiles after path/query tickets no longer reference unsafe backend state or use revision invalidation.

STEP 6
    Test cross-region path over tile boundary.

======================================================================
PSEUDOCODE
======================================================================
STREAM NAV:
    desired profiles := region desired residency
    for profile,tile:
        key := hash(region source rev, tile coord, build config)
        artifact := cache.get or build
    commit phase:
        if generation still current:
            backend.addTile(artifact)
            residency[profile].add(tile)

PATH:
    snapshot records navRevision
    if revision changes before async result publish:
        mark Stale/Retry

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Tile build jobs parallel; dtNavMesh add/remove synchronized through nav owner. Queries use revision snapshots.

======================================================================
ERROR HANDLING
======================================================================
Path requests return typed status Success/Partial/NoPath/Unloaded/Cancelled/Invalid and never fabricate a route through unknown regions.

======================================================================
DETERMINISM RULES
======================================================================
Tile key and commit order stable by region/tile/profile IDs.

======================================================================
PERFORMANCE RULES
======================================================================
Artifact cache avoids repeated rasterization; tile size benchmarked for build/query/stream balance.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Native navigation is largely new capability; SOURCE movement/reference behavior is
preserved where tests exist but inefficient absence of global nav is not parity.
