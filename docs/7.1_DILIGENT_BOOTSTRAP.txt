PUBLIC CONTRACTS
======================================================================
1. RenderBackend lifecycle: create(config)->device/context/queues, create surface/swapchain only for windowed app, beginFrame/endFrame, waitIdle, shutdown. Headless/null backend remains possible.

2. Diligent IRenderDevice/IDeviceContext/ISwapChain never appear in public engine/world/module headers.

3. Backend selection is explicit: D3D12 on Windows preferred, Vulkan cross-platform preferred; capability fallback policy is reported, not hidden.

4. Initial window integration may use a minimal platform layer chosen in implementation chapter, but renderer bootstrap must also support offscreen/no-swapchain tests.

======================================================================
PSEUDOCODE
======================================================================
CREATE:
    backend := choose requested backend
    factory := diligentFactory(backend)
    enumerate adapters
    adapter := select(config)
    create device + immediate context
    query features
    if windowed: create swapchain(surface)
    return RenderBackend

FRAME:
    acquire backbuffer
    transition/clear
    submit
    present

SHUTDOWN:
    stop new frames
    waitIdle
    destroy frame resources
    release swapchain/context/device

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Three.js SOURCE remains visual/reference evidence; native renderer does not attempt API parity with Three.js.
