======================================================================
PUBLIC CONTRACTS
======================================================================
1. Detonation strategy explicitly defines fuze mode/armed state. Current compatibility profile supports armed contact fuze only; unsupported delayed/programmed modes fail/are not silently simulated.

2. Surface candidate must be refined to actual convex/semantic surface point before contact fuze detonates.

3. Nose-crush kinetic work budget is finite and separated from explosive energy.

4. Fragmentation profile defines requested count, body mass fraction, explosive
energy fraction, mass spread and deterministic pattern. Fragment set conserves
represented mass/energy according to profile ledger.

Global active-fragment admission for the SOURCE compatibility world is bounded
by BallisticsWorld.maxFragments = 2048. Fragment-profile requested count and
world capacity are separate concepts.

5. Opposite radial fragment pairs are generated together; capacity truncation drops complete pairs where possible and records omitted mass/energy instead of increasing survivors.

6. Blast is an event/command with origin, radius/profile, energy and seed; destruction/rubble consumers apply geometry/material effects.

======================================================================
DATA LAYOUT
======================================================================
FragmentSpawn array emitted to pending projectile store; each has child TraceId/parent, mass, diameter, velocity, seed. DetonationEvent is immutable and records energy split.

STEP 5

STEP 6
    Apply capacity selection by whole pair/stable priority and record dropped fragment energy/mass as unrepresented.

PSEUDOCODE
======================================================================
DETONATE:
    Eexplosive := strategy.explosiveEnergy(ammo)
    Eradial := Eexplosive * fragmentation.energyFraction
    Mfrag := bodyMass * fragmentation.bodyMassFraction

    weights := seededMassWeights(count, spread)
    normalize(weights)

    for pair i in deterministic pair order:
        m1,m2 := masses
        radialDir := seededUnitDirectionPair(i)
        e1,e2 := proportional energy
        v1 := inheritedVelocity + radialDir * sqrt(2*e1/m1)
        v2 := inheritedVelocity - radialDir * sqrt(2*e2/m2)
        candidatePairs.push(...)

    selectedPairs := capacityBoundWholePairs(candidatePairs)
    ledger.fragmentEnergy += represented radial energy
    ledger.unrepresentedEnergy += omitted radial/body energy
    ledger.explosiveEnergy += Eexplosive
    emit BlastCommand(Eblast)
    mark parent detonated

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Detonation calculations parallel per projectile. Fragment admission to global capacity resolved in deterministic commit phase, not race on atomic counter.

======================================================================
ERROR HANDLING
======================================================================
Invalid fragmentation profile (fractions >1, nonpositive masses) rejected at catalog load. Capacity zero still emits blast and records all fragment budget unrepresented.

======================================================================
DETERMINISM RULES
======================================================================
Pattern/mass weights from projectile seed + detonation semantic path. Pair selection stable independent of worker scheduling.

======================================================================
PERFORMANCE RULES
======================================================================
Bound fragment count and active fragment pool. Batch fragment spawn. Benchmark high-rate HE without rendering.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Compatibility profiles preserve current gameplay calibration; label clearly as game model. Trace parent/child relations preserved.
