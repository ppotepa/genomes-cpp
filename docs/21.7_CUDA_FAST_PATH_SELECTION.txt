======================================================================
PUBLIC CONTRACTS
======================================================================
1. Each KernelId has ordered eligible backends with correctness class, minimum workload size/crossover, required capabilities and fallback.

2. Default is portable Diligent compute for GPU-friendly workloads or CPU when transfer/latency dominates. CUDA is selected only if enabled, compatible and benchmark profile supports it.

3. Backend selection cannot change authoritative algorithm version unnoticed; output semantics/tolerances identical to kernel contract.

4. User/debug override CPU/Diligent/CUDA allowed; unsupported forced backend returns clear error/fallback according setting.

5. Telemetry records selected backend, dispatch size, latency and fallback reason.

======================================================================
DATA LAYOUT
======================================================================
KernelBackendPolicy table keyed KernelId; HardwareCapabilities snapshot; ComputePerformanceProfile versioned by broad GPU/backend class, not machine-secret state.

PSEUDOCODE
======================================================================
SELECT(kernel, workSize, caps, config):
    eligible := policy[kernel].backends filtered by caps and enabled
    if forced:
        require forced in eligible or return Unsupported
        return forced
    for backend in policy order:
        if workSize >= backend.minWork and backend.correctnessApproved:
            return backend
    return CPU/reference fallback

EXECUTE:
    backend := select(...)
    token := backend.submit(kernel,args)
    telemetry.record(...)
    if backend runtime failure and fallbackSafe:
        submit fallback with same snapshot/revision

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Selector pure/read-only. Backend failures handled at dispatch boundary, not random worker code.

======================================================================
ERROR HANDLING
======================================================================
Forced unsupported backend explicit. Runtime CUDA loss -> portable fallback if result not partially committed; otherwise discard/retry revision.

======================================================================
DETERMINISM RULES
======================================================================
Selection may vary by hardware but authoritative semantic contract remains. Save/network state never records backend-specific derived floats as identity.

======================================================================
PERFORMANCE RULES
======================================================================
Selection driven by end-to-end benchmarks and workload size; re-evaluate thresholds on major dependency/version changes.
