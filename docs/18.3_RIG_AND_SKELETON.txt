======================================================================
PUBLIC CONTRACTS
======================================================================
1. RigSchema gives stable BoneId/name/parent and semantic category. SkeletonData gives local bind transform, inverse bind and resolved length/reference points for one phenotype.

2. Bone hierarchy is deterministic and independent of loadout/LOD. Equipment later shares same skeleton; it does not create a second skeleton.

3. Face controllers: eyes rotate with eye bones; eyelid deformation is morph-driven, eyelid controllers remain head-relative; lower lip/jaw and cheeks use explicit influence relationships.

4. Bind pose built from phenotype measurements in metres exactly once; no runtime scale trick that changes skeleton hierarchy.

5. Renderer-specific skinning buffers are compiled later from SkeletonData; Diligent types forbidden here.

6. BoneIndex order is fixed by the single TARGET RigSchema. Hand bones use
deterministic left/right, digit and segment order with explicit parent chains.
Loadout selection and weapon presence do not alter schema or bone count.

======================================================================
DATA LAYOUT
======================================================================
Contiguous BoneRecord array indexed by stable BoneIndex; parent index < child where practical. Map semantic BoneId->index built once/cached. Bind Transform arrays contiguous/aligned.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Freeze all 69 TARGET rig names/parents as one schema and document semantic
    categories, attachments and the deterministic finger hierarchy.

STEP 2
    Implement RigBuilder(BodyPhenotype,FacePhenotype)->SkeletonData.

STEP 3
    Compute local/world bind transforms then inverse binds using engine math convention.

STEP 4
    Validate hierarchy acyclic, exactly one root or explicit root policy, finite transforms, positive expected lengths.

STEP 5
    Expose semantic attachment points derived from phenotype/skeleton for later equipment/weapons.

STEP 6
    Build TARGET bind landmark/bone fixtures for short/average/tall/extreme
    phenotypes; imported samples are diagnostic comparisons only.

======================================================================
PSEUDOCODE
======================================================================
BUILD:
    skeleton.resize(schema.bones)
    for bone in schema topological order:
        local := deriveLocalBind(bone.semanticRole, phenotype)
        world := parent == none ? local : world[parent] * local
        inverseBind := inverse(world)
        store(local, world, inverseBind)

VALIDATE:
    DFS hierarchy no cycle
    all finite
    parent indexes valid
    required names exactly once
    attachment landmarks finite

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
RigBuilder pure per phenotype. SkeletonData immutable after creation; runtime pose buffers are separate per unit/presentation.

======================================================================
ERROR HANDLING
======================================================================
Missing required phenotype landmark/bone schema inconsistency -> build failure. Never silently put missing bone at origin.

======================================================================
DETERMINISM RULES
======================================================================
Schema array fixed. Bind derivation pure. Bone names/IDs stable across runs/version unless rig version changes.

======================================================================
PERFORMANCE RULES
======================================================================
Build once/cache by phenotype artifact. Bone lookup uses indexed map, not repeated string search in animation hot loop.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Reference metrics may seed tolerances, but TARGET RigSchema and phenotype rules
are the only implementation contract. No alternate rig schema is shipped.
