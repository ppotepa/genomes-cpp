GOAL
======================================================================
Introduce explicit transient-memory lifetimes for frame, job and procedural
work so later generators and systems can avoid allocator churn without creating
a custom general-purpose heap.

This is an executable implementation specification. The implementing agent must
complete every acceptance item before reporting the chapter complete.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. LinearArena owns one or more aligned blocks and supports allocate(size, alignment), reset(), bytesUsed(), capacity(). Individual frees do not exist.

2. ArenaMarker captures an offset/generation and ArenaScope rewinds to the marker on destruction only when LIFO safety is satisfied.

3. ScratchContext is passed explicitly to jobs/generators. It may wrap a worker-local LinearArena but callers never assume a specific worker index.

4. Large allocations above configurable threshold may use dedicated blocks tracked by arena and released on reset/destruction.

======================================================================
DATA LAYOUT
======================================================================
Arena block header is cold metadata. Allocation cursor is a size_t/byte pointer local to the arena. Default alignment >= alignof(max_align_t); custom power-of-two alignment required. No shared_ptr ownership.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Create engine/memory library and public include boundary.

STEP 2
    Implement aligned bump allocation with overflow checks and Result/diagnostic failure policy; zero-size returns a unique policy-defined pointer or nullptr consistently.

STEP 3
    Implement reset retaining first blocks for reuse and releaseExcess() for high-water control.

STEP 4
    Implement ArenaMarker/ArenaScope with generation counter so stale markers assert in development.

STEP 5
    Implement ScratchContext containing memory_resource-like allocate API plus typed makeArray<T>(count) for trivially destructible scratch data.

STEP 6
    Add high-water telemetry counters but no automatic logging per allocation.

STEP 7
    Benchmark arena allocation against repeated operator new for representative small temporary arrays; benchmark is informative only.

======================================================================
PSEUDOCODE
======================================================================
ALLOCATE:
    aligned := alignUp(cursor, alignment)
    end := aligned + size
    if end <= block.end:
        cursor := end
        highWater := max(highWater, used())
        return aligned
    block := acquireBlock(max(defaultBlock, size + alignment))
    cursor := block.begin
    retry

RESET:
    generation += 1
    cursor := firstBlock.begin
    mark all later blocks reusable/releasable

SCOPE:
    marker := arena.mark()
    defer arena.rewind(marker)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
    - Ownership is explicit.
    - Public APIs do not hide global mutable state.
    - Thread safety is documented per type.
    - Cross-thread mutation uses later JobSystem/command-buffer contracts where applicable.

======================================================================
ERROR HANDLING
======================================================================
Expected failures return Result/typed errors. Programmer-contract violations use diagnostics/assertion policy. No exception-driven hot-path control flow.

======================================================================
DETERMINISM RULES
======================================================================
Deterministic output must not depend on pointer values, hash-map iteration order, thread completion order, wall time, or platform-dependent representations.

======================================================================
PERFORMANCE RULES
======================================================================
No hidden per-call heap allocation in hot paths. Add benchmark coverage for performance-sensitive primitives and follow 0.4.
