======================================================================
PUBLIC CONTRACTS
======================================================================
1. SpatialBounds component contains local/global broadphase radius/AABB class and current spatial membership revision; exact world Transform remains separate.

2. DynamicSpatialSystem runs after movement/physics commit, collects entities whose spatial cell/bounds changed and emits batched remove/insert/update to region grids.

3. Cross-region movement transfers membership atomically at commit; query snapshot never sees entity absent from both due to half update.

4. Query returns EntityId candidates; caller validates generation/alive/filter and narrow-phase distance/FOV.

======================================================================
DATA LAYOUT
======================================================================
DynamicSpatialComponent:
    semantic EntityId
    current world AABB/radius/category masks
    spatial revision
    occupied cell/page range metadata

Dynamic grid:
    cell/page headers
    contiguous EntityId entries or packed buckets
    generation/revision
    update scratch for moved entities

Movement systems write transformed bounds to local update buffers. The spatial
index applies a batched deterministic reindex at the spatial commit phase; no
per-entity unordered remove/insert from arbitrary worker threads.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Add SpatialBounds/SpatialMembership generic components.

STEP 2
    Mark spatial dirty when transform moves beyond cached cell/bounds tolerance; avoid update for movement within same cells.

STEP 3
    Batch updates by old/new RegionId then apply under world spatial commit.

STEP 4
    Handle cross-region: insert new then publish membership/removal order according snapshot ownership so query consistency defined.

STEP 5
    Expose through WorldQuery dynamic candidate route.

STEP 6
    Benchmark 10k/100k moving entities at different cell sizes/densities.

======================================================================
PSEUDOCODE
======================================================================
SYSTEM:
    parallelFor transform chunks:
        if cellsFor(newBounds) != membership.cells:
            localCommands.push(SpatialMove(entity,old,new))

COMMIT:
    group moves by region
    for move:
        validate entity generation
        update grids
        membership := new cells/region

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Detection jobs read ECS and write local commands. Grid mutation owned by spatial commit stage; query snapshots read immutable/stable grid revision.

======================================================================
ERROR HANDLING
======================================================================
Invalid/stale entity handles and illegal structural mutation return typed errors or development assertions; expected gameplay failures are not exceptions.

======================================================================
DETERMINISM RULES
======================================================================
Grid membership not semantic ordering. Candidate stable sort only for consumers requiring deterministic order.

======================================================================
PERFORMANCE RULES
======================================================================
Skip same-cell updates, local buckets, benchmark cell size; broadphase replaces O(N²).
