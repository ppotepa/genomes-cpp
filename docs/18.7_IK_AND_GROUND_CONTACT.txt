======================================================================
PUBLIC CONTRACTS
======================================================================
1. TwoBoneIK consumes root/target/pole/bind lengths and returns joint rotations/solution metrics; no renderer objects. Lengths come from phenotype bind skeleton and are constant unless anatomy artifact changes.

2. GroundContact samples authoritative World/Terrain query surface in world coordinates and outputs support target positions/normals/bodyLift/maxIKError.

3. Contact queries may be batched/cached by terrain revision. Cache key includes surface revision and morphology/gear support geometry dependencies.

4. Equipment support samples may expand body clearance but do not claim complete collision/self-collision.

5. IK corrections are presentation/pose results unless owning movement chapter explicitly uses a semantic support state; they must not teleport authoritative world entity unpredictably.

======================================================================
DATA LAYOUT
======================================================================
IKSolution small value struct with angles/quaternions/error/reachable. GroundContactInput/output arrays for two feet plus optional hands/gear support points. Per-entity cached terrain cell sample metadata compact.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement backend-independent TwoBoneIK with law-of-cosines clamp and explicit bend plane.

STEP 2
    Validate bind lengths and unreachable targets; clamp target distance inside [|a-b|+eps,a+b-eps].

STEP 3
    Implement foot phase/support target generation from gait state.

STEP 4
    Implement batched terrain height/normal query for candidate supports and solve pelvis/body lift.

STEP 5
    Apply foot IK then hand/weapon/gear support corrections in documented order; expose residual errors.

STEP 6
    Implement contact cache invalidation on terrain/world surface revision and anatomy/gear revision.

STEP 7
    Translate stance/crouch/prone and uneven-ground fixtures.

======================================================================
PSEUDOCODE
======================================================================
IK:
    toTarget := target-root
    cRaw := length(toTarget)
    c := clamp(cRaw, abs(a-b)+eps, a+b-eps)
    cosRoot := clamp((a*a + c*c - b*b)/(2*a*c), -1, 1)
    cosJoint := clamp((a*a + b*b - c*c)/(2*a*b), -1, 1)
    plane := constructBendPlane(toTarget,pole)
    return rotationsFromGeometry(...), error=abs(cRaw-c)

GROUND:
    for supportPoint in predicted supports:
        surface := world.sampleSurface(x,z,revision)
        target.y := surface.height + soleOffset
        target.normal := surface.normal
    bodyLift := solveMinimalLiftToAvoidPenetration(...)
    solve legs from lifted hips

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Evaluate disjoint entities in parallel. World surface snapshot immutable. Cache writes entity-local; terrain shared read-only.

======================================================================
ERROR HANDLING
======================================================================
Degenerate pole/zero limb -> typed IK failure/fallback bind orientation. Missing surface query returns explicit NoSurface policy, not NaN.

======================================================================
DETERMINISM RULES
======================================================================
Fixed pose inputs + world revision produce stable result. No render interpolation state used as solver authority.

======================================================================
PERFORMANCE RULES
======================================================================
Batch terrain samples; cache unchanged cells/revisions; no full mesh CPU skinning for contact. Benchmark 10k low-detail contact evaluations.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET support, reach and clearance invariants define IK acceptance; selected
quaternion fixtures validate the declared coordinate convention.
