======================================================================
PUBLIC CONTRACTS
======================================================================
1. CUDA backend is optional build feature GENOMES_ENABLE_CUDA=AUTO/OFF/ON. AUTO missing toolkit -> backend disabled, not configure failure. ON missing -> clear error.

2. Backend implements only ComputeService kernels proven useful; it does not expose cudaStream_t/device pointers through generic engine APIs.

3. Device selection records UUID/PCI identity and supports only NVIDIA compatible device. Generic Diligent compute remains cross-vendor production path.

4. Benchmark includes transfer/synchronization overhead and compares same workload/result semantics.

5. No kernel moves authoritative state solely to CUDA without generic fallback.

======================================================================
DATA LAYOUT
======================================================================
CudaBackend private stream/event/device buffers. Generic ComputeBuffer handles map through backend-local table. Capability struct reports supported kernels/interoperability.

======================================================================
PSEUDOCODE
======================================================================
INIT:
    if option OFF: unavailable
    if AUTO and toolkit/device absent: unavailable
    if ON and absent: error
    enumerate devices
    select configured/matching render candidate later
    create streams/events

SUBMIT:
    upload if buffer not resident
    launch kernel on stream
    record event
    return ComputeToken(event)

BENCH:
    for workload size:
        measure CPU
        measure Diligent compute end-to-end
        measure CUDA upload+kernel+download
        record crossover and GPU contention

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
CUDA API backend synchronization private. Multiple streams only with explicit data dependencies/events. CPU jobs never directly own cudaStream.

======================================================================
ERROR HANDLING
======================================================================
CUDA runtime/device loss -> backend unavailable and generic fallback where possible. Never crash because optional device absent.

======================================================================
DETERMINISM RULES
======================================================================
Kernel result tolerance/authority follows owning algorithm. CPU reference remains canonical.

======================================================================
PERFORMANCE RULES
======================================================================
No acceptance from TFLOPS/kernel-only. Measure total latency, throughput, VRAM, overlap and render contention.

MIGRATION / COMPATIBILITY
