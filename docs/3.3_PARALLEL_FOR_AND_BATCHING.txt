======================================================================
PUBLIC CONTRACTS
======================================================================
1. parallelFor(begin,end,grain,fn) partitions a half-open range into stable ranges; fn receives BatchRange and JobContext.

2. Partition identity is deterministic from input range/grain; scheduling order is not.

3. Automatic grain policy may estimate targetJobs = workerCount * oversubscription (default 4), but exact semantic reductions must use fixed partition/reduction tree.

4. Nested parallelFor avoids explosive task creation: small/nested ranges may execute inline.

======================================================================
DATA LAYOUT
======================================================================
Use compact value types, explicit ownership, contiguous storage in hot paths, and no hidden shared mutable state.

======================================================================
PSEUDOCODE
======================================================================
PARTITION:
    count := end-begin
    batches := ceil(count/grain)
    for b in [0,batches):
        lo := begin + b*grain
        hi := min(end, lo+grain)
        submit job(batchIndex=b, [lo,hi))

STABLE MAP:
    outputs.resize(batchCount)
    parallelFor batches:
        outputs[batchIndex] = process(range)
    wait
    merge outputs in ascending batchIndex
