======================================================================
PUBLIC CONTRACTS
======================================================================
1. Every detached material volume is in exactly one representation bucket: SOURCE_ATTACHED, HERO, CHEAP, BAKED, or explicitly REMOVED_BY_DAMAGE with ledger entry.

2. Budgets are policy, never deletion rules. HERO overflow -> CHEAP; CHEAP overflow
-> BAKED/direct deposit.

Pinned SOURCE compatibility profile:
    maxDebris        = 512 total hero records/bodies
    maxActiveDebris  = 128 active hero bodies
    maxCheapDebris   = 1024 cheap records
    settleGraceTicks = 60 at 60 Hz (= 1 second compatibility grace)

These are profile values for parity, not generic engine compile-time limits.

3. Demotion decision uses stable priority tuple (importance, awake/sleep state, age, stable ID) and never container iteration accident.

4. Settling is two-phase: deposit all candidates/build new static pile representation, then retire old dynamic bodies, preventing one-frame collision holes.

5. RepresentationAccounting reports per-bucket volume and per-material totals.

======================================================================
DATA LAYOUT
======================================================================
DebrisRecord stores stable debris ID, source component IDs, material volumes, transform/linear/angular state, representation enum, age/ticks, importance. No render pointer in semantic record.

PSEUDOCODE
======================================================================
SPAWN DETACHED:
    packet := makeMaterialPacket(component)
    if heroEligible(packet) and heroAwakeCount < heroBudget:
        create HERO record
    else if cheapCount < cheapBudget:
        create CHEAP record
    else:
        enqueue DirectBake(packet)

SETTLE:
    candidates := collectSettledInStableIdOrder()
    for record in candidates:
        rubble.deposit(record.materialVolumes, record.worldState)
    rubble.flushDirty()
    barrier/commit successful
    for record in candidates:
        retire dynamic representation
        record.representation := BAKED

ACCOUNT:
    total := attached + hero + cheap + baked + removedByDamage
    compare to originalSourceVolume by material

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Lifecycle decisions can be computed per region but quota arbitration/commit is deterministic. Physics commands are buffered; render proxies subscribe after semantic representation transition.

======================================================================
ERROR HANDLING
======================================================================
Failed HERO collider creation falls back to CHEAP/BAKED with diagnostic; never loses material. Failed rubble deposit is fatal/transaction rollback because conservation would be violated.

======================================================================
DETERMINISM RULES
======================================================================
Stable priority/tie-break IDs. Settle commit ordered by debris ID/region. No dependence on Jolt body allocation order.

======================================================================
PERFORMANCE RULES
======================================================================
Bound active rigid bodies. Demotion/bake naturally reduces expensive state. Track counts and transition rates in telemetry.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Preserve current default conceptual budgets as compatibility profile; exact counts may be retuned only by explicit benchmark chapter.
