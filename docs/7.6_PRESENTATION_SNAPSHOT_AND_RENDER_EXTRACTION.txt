======================================================================
PUBLIC CONTRACTS
======================================================================
1. PresentationSnapshot contains only render-relevant immutable records keyed by stable semantic IDs plus interpolation samples/timestamps; no mutable ECS pointers.

2. Publisher uses 2 or 3 slots with ownership state Free/Writing/Published/Reading. Simulation never waits on renderer except bounded backpressure policy chosen explicitly.

3. Extraction computes Added/Updated/Removed using revision counters/dirty sets supplied by simulation/world, not O(N) deep comparison where avoidable.

4. Renderer may consume latest complete snapshot and skip intermediate visual snapshots; authoritative simulation continues independently.

======================================================================
DATA LAYOUT
======================================================================
Public renderer-facing handles are compact generational values. Backend objects are private implementation data.

======================================================================
PSEUDOCODE
======================================================================
PUBLISH:
    slot := exchange.acquireWritable()
    fill immutable arrays
    slot.tick := tick
    memoryFenceRelease()
    exchange.publish(slot)

RENDER:
    slot := exchange.acquireLatest()
    extraction := diff(previousRenderedRevisionMap, slot)
    gpuScene.apply(extraction)
    render(slot.interpolation)
    exchange.release(slot)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.

MIGRATION / COMPATIBILITY
