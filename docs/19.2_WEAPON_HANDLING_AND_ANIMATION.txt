======================================================================
PUBLIC CONTRACTS
======================================================================
1. WeaponState stores selected/active slot, handling state, action phase/time, requested readiness/grip, aim, recoil springs, trigger/pending shot and shot sequence. It does not own renderer weapon instances.

2. WeaponHandlingSystem consumes entity locomotion/pose capability, Equipment resolved weapon slots and WeaponArtifact attachments; outputs WeaponPoseTasks and FireIntent/FireRequest candidate.

3. Hand ownership is explicit per hand/tick. 2H support transitions are weighted and bounded; 1H leaves free hand available.

4. Draw/holster transition guards PRONE_MOVE/REST and sprint/readiness/grip error rules as versioned gameplay policy.

5. Aim target world->local conversion uses snapshot transforms; animation overlay composes before final pose publish, not by mutating render bone tree.

======================================================================
DATA LAYOUT
======================================================================
Hot WeaponState compact ECS component. WeaponPoseTask fixed two-hand array: target transform, weight, curl/profile, attached flag. Cold handling profiles catalog-side.

======================================================================
PSEUDOCODE
======================================================================
STEP:
    update draw/holster state machine(dt)
    supportSpring -> target(grip == 2H and held)
    readinessSpring -> requestedReadiness * sprintSuppression
    recoilSpring -> 0
    tasks := buildGripTasks(activeWeapon, aim, supportWeight)

CAN FIRE:
    active firearm
    state == HELD
    readiness >= threshold
    !forbiddenBodyTransition
    sprintWeight < threshold
    gripError < threshold
    fireCadence permits current tick

ON SHOT INTENT:
    shotSequence++
    recoil impulse state update
    emit FireIntent(entity, WeaponId, AmmoId, shotSequence, muzzle semantic transform)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Weapon handling entity-local parallel. It reads published Infantry pose/locomotion inputs and writes weapon state/task buffers. Fire intents stable-merged.

======================================================================
ERROR HANDLING
======================================================================
Selected slot missing after equipment change -> controlled reset to STOWED and cancel pending shot. Unsupported grip/profile -> validation error.

======================================================================
DETERMINISM RULES
======================================================================
Fixed tick springs/state; shot sequence and seed derivation stable. Aim inputs authoritative/game state, not render interpolation.

======================================================================
PERFORMANCE RULES
======================================================================
No matrix-world traversal through scene graph. Attachment transforms compiled/cached. Batch by handling profile where useful.

MIGRATION / COMPATIBILITY
