======================================================================
PUBLIC CONTRACTS
======================================================================
1. ProjectileState schema version starts as native equivalent of projectile-state-3 and includes stable projectileId, shotId, traceId, optional parentTraceId, world position/velocity, quaternion orientation, bodyForward, angular velocity, inertia/inverse inertia, mass, diameter, dragDiameter, integrity, deformation, stability, impactIndex, ricochetCount, age/travel and energy ledger.

2. Energy ledger fields remain explicit: materialWork, contactLoss, targetWork, flightWork, fragmentEnergy, unrepresentedEnergy, rotationWork, explosiveEnergy, blastEnergy. balanceError is derived, never stored as corrected truth.

3. AmmunitionStrategy owns aerodynamic/contact/material-work/detonation/breakup decisions. Energy+diameter alone are not a ballistic table.

4. Catalog entries include caliberId, strategyId, variantId, construction/calibration and legacy-compatible gameplay values. Exact calibration remains game-model data.

5. State mutation occurs only through typed transitions/functions; systems do not manually edit mass/diameter/inertia inconsistently.

PSEUDOCODE
======================================================================
CREATE:
    dir := normalize(request.direction)
    state.mass := ammo.mass
    state.diameter := ammo.diameter
    state.v := dir * ammo.muzzleVelocity[weapon]
    state.orientation := rotationBetween(+Z, dir)
    refreshInertia(state)
    initialEnergy := 0.5 * mass * dot(v,v)
    ledger := zero

TRANSITION:
    oldRot := rotationalEnergy(state)
    apply bounded mass/diameter/integrity/deformation/stability changes
    refreshInertia(state)
    if newRot > 0:
        angularVelocity *= sqrt(oldRot / newRot)
    impactIndex += 1

BALANCE:
    initialTrans + initialRot + flightWork + rotationWork + targetWork + explosiveEnergy
    - currentTrans - currentRot - materialWork - contactLoss
    - fragmentEnergy - unrepresentedEnergy - blastEnergy

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Projectile state belongs to ballistics storage/chunk owner. Strategies/catalogs immutable. Parallel batches own disjoint projectile ranges or emit transitions into command buffers.

======================================================================
ERROR HANDLING
======================================================================
Invalid ammo/weapon pairing, nonfinite vectors, nonpositive mass/diameter -> typed error. Missing strategy/catalog -> NotFound, never silent fallback in production.

======================================================================
DETERMINISM RULES
======================================================================
All IDs/seeds stable. Strategy randomness derives from projectile seed + semantic event path/impactIndex. No global RNG.

======================================================================
PERFORMANCE RULES
======================================================================
Keep hot projectile state compact; cold verbose calibration metadata remains catalog-side. No per-tick allocation.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Preserve current catalog/profile values as v1 fixtures. Intentional calibration changes require new strategy/version and parity note.
