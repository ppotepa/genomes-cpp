======================================================================
PUBLIC CONTRACTS
======================================================================

1. ACQUISITION METHOD

Primary dependency acquisition method:

    git submodules pinned by the parent Genomes commit.

Reason:

    - exact source revision is visible in Git,
    - offline rebuild after recursive clone is possible,
    - no network access is required during ordinary CMake configure,
    - dependency update is an explicit source-control change,
    - large dependencies do not re-download per build directory.

Forbidden as default architecture:

    FetchContent tracking master/main
    ExternalProject downloading at configure/build time
    unpinned ZIP URLs
    system-wide "whatever version is installed" for core libraries


2. PINNING RULE

Every dependency is pinned by exact submodule commit SHA.

If the project additionally records a release/tag, record BOTH:

    humanVersion = "v5.6.0"
    exactCommit  = "<immutable SHA>"

The SHA is authoritative.

Never specify only:

    master
    main
    latest
    vX without verifying immutable source


3. UPDATE RULE

Dependency update is its own deliberate change.

Required sequence:

    inspect release/changelog
    update submodule commit
    clean configure/build
    run owning subsystem tests
    run dependency smoke tests
    record version/SHA/license
    commit as dependency update

Do not casually update dependencies while implementing unrelated gameplay.


4. THIRD-PARTY COMPILE POLICY

Third-party code:

    may use its upstream warning policy
    must NOT inherit GENOMES_WARNINGS_AS_ERRORS by accident
    is considered SYSTEM/external for warnings where appropriate

Genomes wrappers/adapters:
    use full Genomes warnings.


5. TYPE LEAK POLICY

Diligent types:
    only engine/render/diligent and narrowly scoped render implementation files.

Jolt types:
    only engine/physics/jolt and narrowly scoped bridge implementation files.

Recast/Detour types:
    only engine/navigation/recast and narrowly scoped bridge files.

Public domain headers expose Genomes types/handles.


6. LICENSE POLICY

Every native external library requires:

    name
    source URL
    pinned revision
    version/tag if available
    license identifier
    local license path
    usage scope

Record in:

    docs/THIRD_PARTY_NATIVE.txt

No dependency may ship without license metadata review.


7. DILIGENT SCOPE

Initial Diligent acquisition:

    complete official DiligentEngine meta repository recursively,
    but build only modules explicitly required by Genomes.

Initial target intention:
    Core required by renderer.

Initial exact upstream options:
    DILIGENT_BUILD_TOOLS   OFF
    DILIGENT_BUILD_FX      OFF
    DILIGENT_BUILD_SAMPLES OFF
    DILIGENT_BUILD_DOCS    OFF
    DILIGENT_BUILD_TESTS   OFF

Enable Tools/FX later only if a concrete renderer/tool chapter requires them.
The pinned Diligent revision remains authoritative if option names change.

Backend pruning is explicit per platform using current upstream options such as:
    DILIGENT_NO_DIRECT3D11
    DILIGENT_NO_DIRECT3D12
    DILIGENT_NO_OPENGL
    DILIGENT_NO_VULKAN
    DILIGENT_NO_METAL
    DILIGENT_NO_WEBGPU

For the current LT v1.0 Genomes target:
    Windows keeps D3D12 as the production backend.
    Linux/Vulkan is outside this work package and is not a supported result.
Other backends are not built merely because upstream can build them.

This LT v1.0 decision supersedes the earlier cross-platform backend intention
in this historical chapter. The active production composition is validated by
`cmake/GenomesDependencies.cmake` and `ADR_LIGHTWEIGHT_TOOLKIT.md`.

Official Diligent documentation currently describes:
    CMake integration via add_subdirectory,
    modular Core/Tools/FX structure,
    Direct3D12/Vulkan and other backends,
    recursive submodules.

Genomes must NOT build Diligent samples as part of normal game build.


8. JOLT SCOPE

Pin a stable Jolt release.

At manual authoring baseline, official Jolt release page reports v5.6.0 as the
latest stable release.

Implementation agent MUST re-check official releases at implementation time.
Do not silently switch to a newer release; if a newer candidate is chosen,
record the reason and exact SHA.

Initial Genomes use:
    physics backend only.

Samples/viewer:
    OFF.

Jolt v5.6.0 also contains its own optional GPU compute interfaces for DX12,
Vulkan and Metal. Genomes does NOT adopt those as a second generic compute
architecture. For initial integration disable Jolt GPU/CPU compute modules when
the pinned upstream CMake supports:
    JPH_USE_DX12=OFF
    JPH_USE_VK=OFF
    JPH_USE_MTL=OFF
    JPH_USE_CPU_COMPUTE=OFF

unless a later measured physics-specific chapter explicitly requires them.

Reason:
    generic GPU workloads belong to Genomes ComputeService/Diligent;
    physics must not silently create a second device/queue/resource ecosystem.

Jolt's own release history documents custom job-system integration facilities;
actual adapter is Chapter 13.3.


9. RECAST / DETOUR SCOPE

Pin official recastnavigation repository to an exact commit/release.

Build target intent:

    Recast
    Detour
    DetourCrowd only if later chapter explicitly needs it
    DetourTileCache if Chapter 14 requires it

Current upstream CMake option names at audit baseline:
    RECASTNAVIGATION_DEMO     OFF
    RECASTNAVIGATION_TESTS    OFF
    RECASTNAVIGATION_EXAMPLES OFF

Optional:
    RECASTNAVIGATION_DT_POLYREF64
must be decided by large-world/nav reference requirements, not enabled blindly.

Pinned upstream revision is authoritative if names change.

Tiled navigation is a target requirement, but backend-specific usage starts in
Stage 14.


10. OPTIONAL CUDA

CUDA is NOT acquired as a mandatory source dependency in Stage 1.

Chapter 21 will:
    detect CUDA SDK/toolchain optionally,
    build backend conditionally,
    preserve CPU/Diligent compute fallback.

No standard Genomes target may fail configure merely because CUDA is absent.

IMPLEMENTATION STEPS
======================================================================

STEP 1 - VERIFY 1.1

Before adding external sources:

    clean configure
    clean build
    foundation_smoke pass

If 1.1 is not green:
    do not hide the problem by adding dependencies.


STEP 2 - CREATE external/README.txt

Explain:

    external/ is third-party source only.
    Do not edit vendor source to implement Genomes features.
    Any patch must be documented and preferably maintained as upstreamable
    patch/commit rather than silent local edits.


STEP 3 - ADD PINNED SUBMODULES

Conceptual commands:

    git submodule add <Diligent official URL> external/DiligentEngine
    git submodule add <Jolt official URL> external/JoltPhysics
    git submodule add <Recast official URL> external/recastnavigation

Then checkout exact desired commits.

For Diligent:

    initialize recursively

because official meta repository itself uses submodules.

Implementation report records exact SHAs.


STEP 4 - CREATE docs/THIRD_PARTY_NATIVE.txt

For all three dependencies record:

    source
    SHA
    version/tag if any
    license
    local license file
    scope
    optionality


STEP 5 - CREATE GenomesThirdParty.cmake

Purpose:
    utility functions for third-party target isolation.

Conceptual helper:

    function(genomes_mark_third_party target)
        if target exists:
            mark relevant includes SYSTEM where safe
            do not apply project warning function
    endfunction()

Do not mutate compiler warning flags globally.


STEP 6 - CREATE GenomesDependencies.cmake

It validates submodule presence before add_subdirectory.

Pseudocode:

    function(require_submodule path name):
        if NOT EXISTS expected file:
            message FATAL_ERROR with:
                "Missing <name>. Run git submodule update --init --recursive"

Then configure upstream options BEFORE add_subdirectory.


STEP 7 - DILIGENT CONFIGURATION

Before add_subdirectory, for the audited upstream option set:

    DILIGENT_BUILD_TOOLS   = OFF
    DILIGENT_BUILD_FX      = OFF
    DILIGENT_BUILD_SAMPLES = OFF
    DILIGENT_BUILD_DOCS    = OFF
    DILIGENT_BUILD_TESTS   = OFF

Disable unused graphics backends per target platform rather than compiling
every backend by default.

Tools/FX may be enabled later only when an owning chapter demonstrates the
dependency and updates THIRD_PARTY_NATIVE.

If official Diligent option dependency forces Tools/FX state:
    follow upstream option contracts,
    document exact minimal module set.

Add:
    external/DiligentEngine

but DO NOT link Diligent into genomes_foundation.


STEP 8 - JOLT CONFIGURATION

Disable upstream sample/viewer/test extras not required by Genomes normal build.

For pinned Jolt 5.6.0 compatibility, disable Jolt's optional GPU/CPU compute
interfaces initially where CMake options exist:
    JPH_USE_DX12
    JPH_USE_VK
    JPH_USE_MTL
    JPH_USE_CPU_COMPUTE

Genomes ComputeService remains the sole generic compute abstraction.

Add Jolt source tree in the supported upstream manner.

Do not link Jolt into foundation.


STEP 9 - RECAST CONFIGURATION

At current upstream baseline configure:
    RECASTNAVIGATION_DEMO=OFF
    RECASTNAVIGATION_TESTS=OFF
    RECASTNAVIGATION_EXAMPLES=OFF

If the pinned revision differs, inspect its root CMakeLists and record exact
equivalent option names.

Enable core libraries needed later.

Do not link Recast into foundation.


STEP 10 - ADD NATIVE DEPENDENCY SMOKE TARGET

Create a small Stage-1-only test target:

    genomes_test_dependencies_smoke

Goal:
    prove required library targets configure/link.

It may include one minimal public header from each dependency but MUST NOT
initialize a renderer or physics world yet.

If static link causes unnecessary platform bootstrap complexity, separate
compile-target smoke tests are acceptable, but document why.


STEP 11 - VERIFY NO TYPE LEAK

Search project-owned public headers:

    engine/foundation/include/**
    future generic public headers

Assert no include paths containing:

    Diligent
    Jolt
    Detour
    Recast

except their own backend directories once those exist.


STEP 12 - CLEAN BUILD

Delete build directory.

Reconfigure from clean tree with recursive submodules present.

Build Debug.

Run:
    foundation_smoke
    dependency smoke


STEP 13 - MISSING-SUBMODULE NEGATIVE TEST

Temporarily verify configuration failure message is understandable when a
required dependency directory is absent/uninitialized.

Do NOT leave the repository broken.

Acceptance is that the error says what command resolves it.


STEP 14 - LEGACY SANITY

Run:
    node tests/check_core.js

if supported.

Dependency addition must not alter browser runtime.


======================================================================
PSEUDOCODE
======================================================================

DEPENDENCY VALIDATION:

    function requireSubmodule(path, expectedFile, displayName):
        if not exists(path / expectedFile):
            fatal(
                displayName
                + " is not initialized. "
                + "Run: git submodule update --init --recursive"
            )


DEPENDENCY REGISTRATION:

    function configureDependencies():
        requireSubmodule(Diligent)
        requireSubmodule(Jolt)
        requireSubmodule(Recast)

        configureDiligentMinimal()
        addSubdirectory(Diligent)

        configureJoltMinimal()
        addSubdirectory(Jolt)

        configureRecastMinimal()
        addSubdirectory(Recast)


VERSION/PIN REVIEW:

    function updateDependency(dep, candidateRevision):
        changelog := readUpstreamChangelog(candidateRevision)
        license   := readLicense(candidateRevision)

        if license incompatible:
            reject

        checkout exact candidateRevision

        cleanConfigure()
        buildAll()
        runOwningSubsystemTests()

        if any required test fails:
            revert dependency revision

        record exact SHA + version + license

======================================================================
THREADING / OWNERSHIP RULES
======================================================================

No dependency may create a permanent runtime thread merely by being linked.

Actual worker/physics/render thread ownership is defined in owning chapters.

Stage 1 performs no runtime initialization.

======================================================================
ERROR HANDLING
======================================================================

Uninitialized required submodule:
    CMake FATAL_ERROR with remediation command.

Unsupported upstream configuration:
    fail clearly rather than silently enabling huge optional components.

License metadata missing:
    chapter incomplete.

======================================================================
DETERMINISM RULES
======================================================================

Dependency source revision is part of reproducibility.

"Same Genomes commit" must identify exact dependency commits through submodules.

Do not permit configure-time network resolution to change dependency code.

======================================================================
PERFORMANCE RULES
======================================================================

Do not benchmark dependency examples as proof of Genomes performance.

Do not build samples/demos in normal developer path.

Keep dependency compilation isolated so incremental Genomes code rebuilds do not
unnecessarily rebuild vendor source.

Legacy JS libraries remain.

Native dependency tree is additive.

No browser path switches to Diligent/Jolt/Recast in Stage 1.
