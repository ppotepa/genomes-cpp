======================================================================
PUBLIC CONTRACTS
======================================================================
1. AnimationSystem operates on batches/chunks, not one virtual Update per unit. Stages: sample locomotion/posture -> contacts/IK -> face -> weapon overlay later -> finalize pose channels -> publish presentation pose snapshot.

2. AnimationLOD changes evaluation frequency/detail but not genome, skeleton identity, gait logical phase or authoritative world transform.

3. Near/combat visible tiers may evaluate 60Hz; mid 30/15; distant/offscreen lower/zero presentation where safe. Exact policy configurable and camera can affect presentation only.

4. Previous/current pose snapshots enable render interpolation; simulation pose writes are not read while workers mutate them.

5. GPU skinning consumes skeleton/morph channel snapshot; CPU does not skin every vertex each tick for ordinary rendering.

======================================================================
DATA LAYOUT
======================================================================
PoseBuffer uses contiguous bone quaternion/translation arrays per batch/artifact archetype; previous/current double buffers. Per-entity small channel state references shared SkeletonData.

======================================================================
PSEUDOCODE
======================================================================
TICK:
    dueBatches := cadence.collectDue(animationEntities)
    jobs.sample := parallel_for batches -> sampleLocomotionPose
    jobs.contact := after sample -> groundContactIK
    jobs.face := parallel/after required roots -> faceChannels
    jobs.finalize := after contact+face -> combinePose
    wait finalize
    swap previous/current pose buffers
    publish poseRevision

RENDER:
    alpha := simulationSnapshot.interpolationAlpha
    poseRender := interpolate(previous,current,alpha)
    upload bone/morph buffers for visible GPU instances

LOD CHANGE:
    set tier
    do not reset phase/timers
    on next due evaluation sample state at current SimulationTick

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Pose buffers double-buffered; each job owns entity range. Shared skeleton immutable. Renderer sees published snapshot only.

======================================================================
ERROR HANDLING
======================================================================
Missing skeleton/channel layout fails entity presentation artifact registration; do not partially index wrong bones.

======================================================================
DETERMINISM RULES
======================================================================
Within same LOD/cadence/ticks outputs deterministic; camera affects presentation scheduling only, not gameplay movement/AI. Worker merge not needed for disjoint pose arrays.

======================================================================
PERFORMANCE RULES
======================================================================
Grain-size benchmark, no full matrix-tree updates unless needed, skip unchanged channels, GPU skinning. Report CPU ms and pose evaluations count by tier.
