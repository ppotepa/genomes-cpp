======================================================================
PUBLIC CONTRACTS
======================================================================
1. Compiler input immutable TerrainArtifact + render profile; output RenderArtifact/mesh pages referencing GPU handles only in render layer.

2. Terrain LOD uses same authoritative height samples/downsample policy; borders match adjacent LOD via skirts/stitch indices or clipmap strategy chosen here and tested.

3. Chunk bounds are exact/conservative from height range and world bounds, enabling GPU/CPU culling.

4. Material coloring moves to shader field/texture or compiled vertex data but does not alter semantic height.

IMPLEMENTATION STEPS
======================================================================

STEP 2

STEP 3
    Upload per-region height/material texture or vertex heights according benchmark; prefer height texture for reusable grid topology.

STEP 4
    Create chunk instance records/bounds in GPUScene.

STEP 5
    Implement seam test across adjacent same/different LOD chunks.

STEP 6
    Add render debug wireframe/chunk bounds channel.

======================================================================
PSEUDOCODE
======================================================================
COMPILE REGION:
    upload height field texture/buffer
    for chunk in region grid:
        record.origin := chunkOrigin
        record.heightRange := minmax
        record.lodSet := sharedGridMeshes
        gpuScene.addTerrainChunk(record)

VERTEX SHADER:
    localGridXZ -> sample height -> world/local position
    normal from field or finite difference texture

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Compiler runs off render thread for CPU recipe prep; GPU resource creation/upload is staged through render service, never direct from generator jobs.

======================================================================
ERROR HANDLING
======================================================================
Invalid procedural candidates return ValidationReport/Result. Active world is changed only through generation transaction commit.

======================================================================
DETERMINISM RULES
======================================================================
Visual LOD may depend on camera; mesh semantic height samples remain fixed.

======================================================================
PERFORMANCE RULES
======================================================================
Reuse index/topology buffers, chunk cull, avoid unique full vertex buffers when height textures are more efficient; benchmark both if needed.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Do not preserve Three.js object structure. Preserve terrain appearance/function and chunk culling capability.
