======================================================================
PUBLIC CONTRACTS
======================================================================
1. GPUScene persistent record IDs are generational handles tied to semantic source IDs in a CPU mapping table.

2. Tables: Transform, Instance, Mesh, Material, BoundingData; Skeleton added later without changing base instance schema.

3. CPU writes staged deltas into upload batches; unchanged records cause zero upload.

4. Static instance pages may upload once and remain immutable until region unload; dynamic transforms use dirty ranges or scatter update strategy.

======================================================================
DATA LAYOUT
======================================================================
Public renderer-facing handles are compact generational values. Backend objects are private implementation data.

PSEUDOCODE
======================================================================
SYNC SNAPSHOT:
    for change in extraction.changes:
        handle := map.getOrCreate(change.semanticId)
        cpuShadow[handle] := encode(change)
        dirty.mark(handle.index)

UPLOAD:
    ranges := coalesce(dirty)
    for range:
        stage copy cpuShadow[range] -> gpuTable[range]
    dirty.clear()

REMOVE REGION:
    for handles in regionGpuPage:
        freeDeferred(handle)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.
