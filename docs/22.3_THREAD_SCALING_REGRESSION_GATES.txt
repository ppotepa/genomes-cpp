GOAL
======================================================================
Convert JobSystem/subsystem scaling benchmarks into regression gates that catch serialization, contention, false sharing and task-granularity regressions without assuming more threads always help.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. Each gate defines workload, hardware class, worker counts, baseline T1/Tp, acceptable regression band and expected qualitative trend. Do not apply one speedup number globally.

2. Correctness/determinism verified before timing. Worker-count semantic hash mismatch is correctness failure independent of performance.

3. Measure total workload including scheduler/merge/barriers. Report work-steal counts, runnable queue latency, idle time, critical-path/serialization spans where telemetry supports.

4. Gate may assert "8 workers no worse than X% of 4" rather than impossible linear speedup for bandwidth-bound work.

5. Dedicated controlled runner required for hard timing gate; generic CI runs smoke/scaling shape only.

======================================================================
DATA LAYOUT
======================================================================
Baseline records by scenario+machine+compiler+dependency profile; performance gate configs versioned with rationale and update history.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Select representative parallel workloads: procedural buildings, city regions, animation, AI, spatial queries, destruction batch, full headless tick.

STEP 2
    Run 1/2/4/8/16/physical-core/SMT counts and record T, speedup, efficiency, utilization.

STEP 3
    Identify expected saturation reason per workload; document serial fraction/memory limit rather than "optimize later".

STEP 4
    Implement regression checker using robust median/variance and machine-specific baseline.

STEP 5
    Add deterministic hash comparison across worker counts before timings accepted.

STEP 6
    Add scheduler counters for steals, failed steals, queue depth, task duration distribution and barrier waits.

STEP 7
    Establish hard gates only on dedicated runner; PR hosted runner checks functional multi-thread path/no catastrophic slowdown.

======================================================================
PSEUDOCODE
======================================================================
SCALING:
    T1 := measure(workload,workers=1)
    for P in [2,4,8,16,...]:
        TP := measure(workload,P)
        speedup := T1/TP
        efficiency := speedup/P
        assert semanticHash(P)==semanticHash(1)
        compare TP to baseline[P] with noise policy

REGRESSION:
    if dedicatedMachine:
        if median > baseline * (1+allowedPct) and statistically/repeated valid:
            FAIL
    else:
        assert completes and no pathological e.g. TP > 2*T1 for workload marked parallel

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Benchmark controls worker count via JobSystem config and waits all work. Avoid OS background variability where possible.

======================================================================
ERROR HANDLING
======================================================================
Machine fingerprint mismatch => no hard gate, report only. Thermal/noise invalidates run.

PERFORMANCE RULES
