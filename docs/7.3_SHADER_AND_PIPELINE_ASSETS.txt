======================================================================
PUBLIC CONTRACTS
======================================================================
1. Shader source language baseline is HLSL-style source compiled/cross-compiled through approved Diligent toolchain/backend path; exact compiler/version becomes part of shader cache key.

2. ShaderAsset key includes source hash, include dependency hashes, entry point, stage, defines, compiler/backend target/version.

3. PipelineAsset contains immutable render/compute state, vertex layout signature, resource layout signature and shader refs.

4. Diligent static/mutable/dynamic resource binding policy is chosen intentionally: frame-global/static data does not become per-draw dynamic binding; persistent material/instance data aims toward bindless/indexed tables when capability allows.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define canonical shader source/include resolver independent from current working directory.

STEP 2
    Implement preprocessor dependency fingerprint and fail on untracked include.

STEP 3
    Compile shaders at build/tool time where practical; runtime developer compile allowed behind explicit mode.

STEP 4
    Reflect resource bindings and validate expected signature.

STEP 5
    Create Diligent pipeline/resource signature/SRB implementation; cache by immutable PipelineAsset key.

STEP 6
    Add shader compile error diagnostics preserving source path/line and generated backend logs.

PSEUDOCODE
======================================================================
SHADER KEY:
    key := hash(
        compilerVersion,
        backendTarget,
        sourceContent,
        sorted(includePath,includeHash),
        entry,
        stage,
        sorted(defines)
    )

PIPELINE:
    if cache.contains(key): return handle
    shaders := loadCompiled()
    validateReflection()
    nativePSO := createPipeline(translate(desc))
    cache.publish(key,nativePSO)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Three.js SOURCE remains visual/reference evidence; native renderer does not attempt API parity with Three.js.
