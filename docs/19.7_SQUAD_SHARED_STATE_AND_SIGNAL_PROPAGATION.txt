======================================================================
PUBLIC CONTRACTS
======================================================================
1. SquadId/group membership is data. SquadSharedState contains shared orders, coarse contacts, route/corridor refs and tactical summaries; individual AI retains local memory/uncertainty.

2. TacticalSignal has source, creationTick, type, subject/location/confidence, hop/TTL and optional channel/range policy. Propagation is explicit delayed event, not instant shared map.

3. Signals merge/deduplicate by semantic key and confidence/timestamp policy. A received contact does not become direct visual LOS; provenance/lastObservedBy retained.

4. Squad calculations operate once per squad/batch where appropriate (shared route, threat summary) and members consume results at their cadence.

5. No signal from enemy/friendly entity leaks through renderer/camera or global singleton.

======================================================================
DATA LAYOUT
======================================================================
SquadState storage keyed SquadId, member EntityId ranges/lists. TacticalSignal compact POD event. Contact summary stores target/position/tick/confidence/source type.

PSEUDOCODE
======================================================================
EMIT CONTACT:
    signal := {source, squad, subject, pos, createdTick, confidence, ttl}
    deliveryTick := tick + communicationDelay(profile,distance)
    signalQueue.schedule(deliveryTick, stableSequence, signal)

DELIVER:
    due := queue.pop(tick)
    stable_sort due by squad, subject, createdTick, sourceId
    for signal:
        existing := squad.contacts[subject]
        if newer/better by explicit policy:
            merge preserving provenance

AI OBSERVATION:
    localVisible := local perception
    sharedContacts := squad contacts with confidence > threshold
    mark shared contacts as reported, not visible

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Squads partitionable; signal scheduling/commit stable. Member AI reads immutable shared snapshot for tick.

======================================================================
ERROR HANDLING
======================================================================
Stale member/squad removed cleanly. Invalid signal subject/range discarded with diagnostic counter according to policy.

======================================================================
DETERMINISM RULES
======================================================================
Tick-based delivery and stable merge order. No wall-clock/network nondeterminism in single-player authoritative simulation.

======================================================================
PERFORMANCE RULES
======================================================================
Shared expensive computations amortized per squad. Bound contacts/signals/TTL. Benchmark memory and updates.
