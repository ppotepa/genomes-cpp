======================================================================
PUBLIC CONTRACTS
======================================================================
1. World validation uses selected scenarios/seeds with an explicit TARGET
feature matrix, never pixel-perfect browser comparison.

2. Compare semantic world hashes/invariants, entity initial states, deterministic tick outcomes for controlled scenarios, impact/destruction accounting and lifecycle/dispose.

3. Useful settlement scenarios are translated to TARGET feature coverage. Their
exact layout is not preserved and no compatibility world generator is shipped.

4. Graphical/headless native modes must produce identical authoritative outcomes for same commands/ticks.

5. Report maps every accepted TARGET world requirement to an automated test or
explicit manual acceptance owner. SOURCE cases are first triaged for product relevance.

6. World fixtures record BuildingSiteRequests and resolved BuildingPlans as
separate layers. SOURCE city placeholder envelopes may validate request
placement, while current modular building runtime/lab fixtures validate plans;
the two evidence types are never compared as the same artifact.

PSEUDOCODE
======================================================================
for scenario in fixtures:
    native := startWorld(scenario.spec)
    for checkpoint in scenario.timeline:
        apply commands at exact tick
        run to checkpoint.tick
        actual := semanticSnapshot(native)
        compare(actual, checkpoint.expected, policy)
    dispose
    assert lifetime/resource counters baseline

graphicalHash := runSameCommands(graphical)
headlessHash := runSameCommands(headless)
