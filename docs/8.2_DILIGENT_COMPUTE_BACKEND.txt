======================================================================
PUBLIC CONTRACTS
======================================================================
1. Diligent backend maps kernel descriptors to compute PipelineAsset and resource signature. Static/mutable/dynamic bindings follow 7.3 policy; no resource-name lookup per dispatch after pipeline creation.

2. Dispatch can execute through RenderGraph pass or explicit compute batch executor; resource transitions are declared.

3. GPU output remains GPU-resident unless caller explicitly requests readback.

4. Backend reports limits: workgroup sizes, dispatch dimensions, storage buffer alignment and queue availability.

======================================================================
DATA LAYOUT
======================================================================
Compute inputs/outputs are explicit buffer/view descriptors with versioned kernel parameter blocks; no backend-native pointer leakage.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement reference vector kernel on GPU with same semantic layout as CPU backend.

STEP 2
    Create compute pipeline cache keyed by kernel/version/defines/backend.

STEP 3
    Pre-resolve resource binding slots/signature to compact binding IDs.

STEP 4
    Add graph pass builder for compute reads/writes and dispatch dimensions.

STEP 5
    Implement completion fence/token integration with render backend.

STEP 6
    Run CPU vs GPU numerical parity for deterministic simple kernels on supported CI/dev GPU.

======================================================================
PSEUDOCODE
======================================================================
PREPARE KERNEL:
    shader := shaderAssets.load(kernel.shaderKey)
    pipeline := pipelineCache.getOrCreate(computeDesc)
    bindings := reflection.resolve(kernel.bindingSchema)

DISPATCH:
    graph.addComputePass:
        declare inputs SRV
        declare outputs UAV
        bind pipeline/resources by resolved slots
        DispatchCompute(groupsX,groupsY,groupsZ)
    return graphCompletionToken

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
CPU prepares immutable dispatch inputs; backend owns GPU resources and synchronization. Readbacks become visible only after completion tokens/fences.

======================================================================
ERROR HANDLING
======================================================================
Unsupported GPU feature selects explicit CPU/fallback path where allowed; shader/dispatch failures return typed errors and diagnostics.

======================================================================
DETERMINISM RULES
======================================================================
GPU-derived advisory fields may be numerically non-bitwise-identical across hardware; authoritative CPU state cannot depend on undocumented nondeterministic reductions.

======================================================================
PERFORMANCE RULES
======================================================================
Batch dispatches, avoid CPU/GPU ping-pong, measure transfer cost separately from kernel cost and prefer GPU-resident pipelines.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET compute service is new infrastructure; SOURCE has no equivalent general
compute layer and remains reference for domain outputs only.
