======================================================================
GOAL
======================================================================
Port the bounded contact/material impact solver so projectile/impact energy,
target motion, impulses, material work and contact continuation are computed in
one explicit state machine without duplicating force/work or heuristic impulses.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. ImpactInput contains projectile/impactor mass, effective diameter/area, full world velocity/angular state, contact point/normal, target linear/angular velocity, target COM lever, MaterialTraversal intervals and strategy/profile refs. Unit direction is never substituted for velocity.

2. Relative velocity at contact = projectileVelocity - (targetLinearVelocity + targetAngularVelocity × lever). Normal/tangential components are explicit. Solver may update world velocity/orientation/deformation through the ammunition/projectile strategy layer later.

3. Material work for each solid interval is W = F_resist * actualTravel, with F_resist = pressure/resistance-law output * projectile cross-sectional area exactly once. Void/air work = 0 while time/travel still advances.

4. ImpactState stores active physicalSolidId, assembly/layer interval, progress distance, entry energy/velocity, cumulative materialWork/contactLoss/targetWork and contact continuity across fixed ticks.

5. ImpactResult returns residual velocity/angular state, projectile impulse, target impulse/torque, structural damage deposition, traversal outcome Continue/Penetrated/Stopped/RicochetCandidate/DetonationCandidate and ledger deltas.

======================================================================
DATA LAYOUT
======================================================================
ImpactState is compact POD-like per active projectile contact. Traversal arrays are small views into immutable MaterialAssembly. Results are value objects appended to projectile/destruction event buffers.

PSEUDOCODE
======================================================================
CONTACT STEP:
    targetPointVelocity := targetLinear + cross(targetAngular, lever)
    relative := projectileVelocity - targetPointVelocity
    normalSpeed := -dot(relative, contactNormal)

    while remainingTravel > 0 and iterations < max:
        interval := current material/air interval
        ds := min(remainingTravel, interval.remaining)

        if interval.kind == Air:
            work := 0
        else:
            pressure := strategy.resistance(materialSample, projectileState, contactState)
            force := pressure * projectileCrossSectionArea
            work := force * ds
            deposit material damage from work/contact geometry

        update projectile energy/velocity according strategy
        state.progress += ds
        ledger.materialWork += work

        if interval complete:
            advance layer preserving contact if same physicalSolidId/contiguous
            end contact on actual gap/interface policy as specified

    residual := independentlyComputeLedgerResidual()
    return result

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Impact solves can run in parallel for independent projectiles against immutable target snapshot. Structural/damage mutations are emitted as commands and committed later. Do not mutate Jolt bodies inside solver.

======================================================================
ERROR HANDLING
======================================================================
Nonfinite inputs, invalid material interval, negative mass/diameter or impossible state return typed ImpactError. Iteration cap reports explicit LimitReached with conserved/unrepresented ledger terms.

======================================================================
DETERMINISM RULES
======================================================================
Fixed-step input snapshot + projectile/target IDs + strategy version define result. Equal-time conflicting damage commits are stable-sorted later; solver itself has no shared RNG unless strategy receives explicit SeedPath.

======================================================================
PERFORMANCE RULES
======================================================================
No allocation per layer/contact. Reuse scratch traversal buffer. Keep branch-heavy solver CPU-side initially; SIMD/batching assessed in 17.5.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Match current SOURCE acceptance first. Any physical-model redesign creates a new ImpactSolver/material/strategy version and new parity fixtures.
