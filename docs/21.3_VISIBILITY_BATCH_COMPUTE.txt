======================================================================
PUBLIC CONTRACTS
======================================================================
1. CPU LOS remains canonical fallback. GPU path only enabled after parity/tolerance and latency policy tests.

2. GPU query input snapshot must match explicit WorldQueryRevision/static/dynamic proxy revision; stale result carries revision and cannot be silently applied to newer world state.

3. Latency policy is one of: same-tick awaited at defined barrier (may stall), previous-compatible-revision advisory, or selective CPU confirmation. Policy chosen by AI chapter/config and measured.

4. GPU acceleration structure can be heightfield/grid/BVH proxy but must include destruction/rubble updates at declared revision.

5. Any ambiguous/near-boundary result may request CPU confirmation rather than force GPU decision.

======================================================================
DATA LAYOUT
======================================================================
LOSRequest buffer, result bit/blocker approximation/revision, compact GPU static proxy/BVH/heightfield. Do not expose Diligent buffers to combat headers.

PSEUDOCODE
======================================================================
DISPATCH:
    token := compute.submit(
        requests,
        worldProxyRevision
    )

CONSUME:
    if !token.ready:
        use policy fallback (previous advisory or CPU)
    result := token.map()
    if result.worldRevision != currentCompatibleRevision:
        discard
    for query:
        if result.ambiguous:
            cpuResult := cpuLOS(query)
        else:
            use result according to authority policy

BENCH:
    measure buildProxy + upload + dispatch + synchronization + readback

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
GPU queue sync explicit. CPU workers continue unrelated work. Do not spin-wait on token.

======================================================================
ERROR HANDLING
======================================================================
Backend unavailable/proxy build failure -> CPU path. Revision mismatch -> discard/fallback.

======================================================================
DETERMINISM RULES
======================================================================
Authoritative outcomes remain CPU-confirmed where GPU nondeterminism/precision can alter discrete boundary. GPU-only advisory may vary.

======================================================================
PERFORMANCE RULES
======================================================================
Fast path accepted only if end-to-end workload wins at realistic batch sizes. Async compute may contend with renderer; benchmark overlap and total frame.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Optimization only; does not alter AI contract.
