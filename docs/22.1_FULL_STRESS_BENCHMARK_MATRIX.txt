======================================================================
PUBLIC CONTRACTS
======================================================================
1. Benchmark scenario is versioned input: engine commit, dependency revisions, compiler/build flags, hardware/OS/driver metadata, seed/world profile, entity/building/vegetation/projectile counts and duration.

2. Separate CPU subsystem benchmarks, headless full simulation and graphical end-to-end. Do not infer subsystem bottleneck from FPS alone.

3. Report median/p95/p99/max where applicable, frame/tick missed deadlines, worker utilization, memory/VRAM high-water, GPU pass timing and IO/streaming stalls.

4. Required workload families: generation, idle large army, movement/navigation, dense perception/AI, sustained firefight, city destruction, streaming traversal, full render city/vegetation/units, combined worst-reasonable scenario.

5. Hosted CI timing is informational; canonical regression baseline uses documented controlled machines or dedicated runners.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define baseline hardware tiers (minimum/reference/high-end) as concrete documented machines when available; until then mark provisional.

STEP 2
    Create deterministic scenario specs/seeds and warmup/measurement durations per 0.4.

STEP 3
    Instrument engine counters and Tracy/PIX/GPU timestamp capture hooks so benchmark names correlate with subsystem spans.

STEP 4
    Run headless generation/simulation matrices and graphical scene matrices in Release with debug validation off except separate diagnostic run.

STEP 5
    Collect thread scaling, memory, frame/tick percentiles, draw/dispatch, upload/readback, physics bodies, nav rebuilds, AI candidates/LOS, projectile/debris counts.

STEP 6
    Repeat enough times to characterize variance; flag noisy results rather than averaging them away.

STEP 7
    Commit raw results and baseline report with bottleneck ranking but no unmeasured claims.

STEP 8
    Establish which scenarios become regression gates in 22.2-22.4.

PSEUDOCODE
======================================================================
FOR machine IN controlledMachines:
    FOR scenario IN benchmarkScenarios:
        warmup(scenario)
        runs := []
        repeat R:
            reset deterministic world
            run scenario exact ticks/frames
            collect metrics
            runs.push(metrics)
        report median,p95,p99,max,variance
        persist raw metadata + commit/dependency SHAs

VALIDATE RUN:
    require Release/RelWithDebInfo policy
    require same scenario hash
    require no test failures
    require no thermal/power anomaly if monitoring available
    mark invalid run rather than cherry-pick
