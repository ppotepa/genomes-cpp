2. TEXT / EQUATION NOTATION
======================================================================

All manual files are plain UTF-8 .txt.

Use both readable mathematical notation and implementation-oriented notation.

Example:

    q = a + t (b - a)

Implementation pseudocode:

    q := a + t * (b - a)

Use:

    :=          assignment / definition in pseudocode
    =           mathematical equality
    ≈           numerical approximation
    !=          implementation inequality
    ∈           membership
    Σ           summation
    Π           product
    ||v||       Euclidean norm
    ||v||²      squared Euclidean norm
    a · b       dot product
    a × b       cross product
    [a, b)      half-open interval
    |S|         cardinality of set S
    det(M)      determinant
    H(...)      deterministic hash function
    floor(x)    mathematical floor
    clamp(x,a,b) = min(max(x,a),b)

ASCII fallback is allowed in code snippets:

    dot(a,b)
    cross(a,b)
    lengthSq(v)
    sum(...)
    in [a,b)

Do not use ambiguous notation such as:

    x^2

inside C++ pseudocode if an implementation agent could interpret ^ as XOR.
Write:

    x*x

in implementation pseudocode.

======================================================================
3. COORDINATE AND UNIT CONVENTIONS
======================================================================

DATA-COORD-001 - WORLD AXES

Canonical semantic world:

    X = horizontal axis
    Y = vertical axis, positive up
    Z = horizontal axis

Basis orientation is defined algebraically:

    e_x × e_y = e_z

This is the canonical right-handed mathematical basis used by engine-level
geometry.

Game semantic convention may call +Z "forward" where appropriate.

Renderer backend conversion, camera convention and clip-space convention MUST
be handled at render boundaries. They do not redefine world mathematics.


DATA-COORD-002 - 2D WORLD GEOMETRY

Planar procedural geometry is represented in the horizontal XZ plane.

A 2D point is written:

    p = (x, z)

Do not use (x,y) in city/road/building-plan mathematics unless the chapter
explicitly states that it is using an abstract 2D coordinate system.


DATA-UNIT-001 - SI UNITS

Unless explicitly stated:

    length          metre [m]
    time            second [s]
    mass            kilogram [kg]
    velocity        m/s
    acceleration    m/s²
    force           newton [N]
    energy          joule [J]
    angle           radian [rad]

UI may display degrees. Core mathematics uses radians.


DATA-MATRIX-001 - MATHEMATICAL TRANSFORM CONVENTION

Conceptually use column vectors:

    p_world = M_world * p_local

Hierarchy:

    M_world = M_parent * M_local

Storage order in memory is an implementation detail of the selected math and
render libraries and MUST NOT alter semantic multiplication order.


DATA-RANGE-001 - HALF-OPEN INDEX RANGES

Container/index iteration uses:

    [begin, end)

unless a formula explicitly describes a closed geometric interval.

======================================================================
4. NUMERICAL ROBUSTNESS
======================================================================

NUM-EPS-001 - NO GLOBAL MAGIC EPSILON

Forbidden:

    constexpr double EPS = 1e-6;

used indiscriminately by all geometry.

Tolerance must be associated with:

    units,
    operation scale,
    semantic purpose.

Examples:

    weld tolerance
    road snap tolerance
    building clearance tolerance
    display comparison tolerance

are different concepts.


NUM-SCALE-001 - SCALE-AWARE COMPARISON

For scalar comparison where approximate equality is semantically appropriate:

    |a - b| <= absTol + relTol * max(|a|, |b|)

Do NOT use approximate equality for IDs, counts, topology, or exact integer
state.


NUM-GEO-PREDICATE-001 - ROBUST PREDICATES

Topological decisions such as:

    orientation,
    collinearity,
    incircle / Delaunay,
    side-of-line classification

must not rely on a casually selected epsilon when an adaptive/exact predicate
is required for correctness.

Primary reference:

    REF-SHEWCHUK-1997

Native geometry chapters must either:

    - use a proven robust predicate implementation,
    - use a library providing filtered/exact predicates,
    - or document why a bounded approximate predicate is safe for that domain.


NUM-NORMALIZE-001 - SAFE NORMALIZATION

For vector v:

    if ||v||² <= threshold²:
        return explicit failure/fallback
    else:
        return v / ||v||

Never hide zero-vector normalization by returning an arbitrary unit vector in
generic math primitives.


NUM-ANGLE-001 - ANGLE WRAP

Canonical signed wrap to (-π, π]:

    wrapPi(a):
        while a <= -π: a += 2π
        while a >   π: a -= 2π
        return a

Performance implementations may use remainder-based equivalents if tests prove
the same boundary convention.

5. BASIC SCALAR MATH

MATH-SCALAR-CLAMP-001

    clamp(x, a, b) = min(max(x, a), b)
    require a <= b


MATH-SCALAR-LERP-001

    lerp(a, b, t) = a + t (b - a)

No implicit clamping of t.


MATH-SCALAR-SMOOTHSTEP-001

For t in [0,1]:

    S3(t) = t² (3 - 2t)

General interval:

    u = clamp((x-a)/(b-a), 0, 1)
    smoothstep(a,b,x) = u²(3 - 2u)


MATH-SCALAR-FADE5-001

Improved Perlin quintic fade:

    F5(t) = 6t^5 - 15t^4 + 10t^3

Implementation pseudocode:

    return t*t*t * (t * (t*6 - 15) + 10)

Reference:

    REF-PERLIN-2002

6. VECTOR MATH
======================================================================

MATH-VEC-DOT-001

For n-dimensional vectors:

    a · b = Σ_i a_i b_i


MATH-VEC-NORM2-001

    ||v||² = v · v
    ||v||  = sqrt(v · v)

Prefer squared distance in comparisons when the actual distance is unnecessary.


MATH-VEC-DIST2-001

    d²(a,b) = ||a-b||²


MATH-VEC-CROSS3-001

For 3D:

    a × b =
        (a_y b_z - a_z b_y,
         a_z b_x - a_x b_z,
         a_x b_y - a_y b_x)


MATH-VEC-CROSS2-001

For horizontal 2D vectors a=(a_x,a_z), b=(b_x,b_z):

    cross2(a,b) = a_x b_z - a_z b_x

This is a scalar signed area factor.


MATH-VEC-PROJECT-001

Projection of v onto nonzero d:

    proj_d(v) = d * (v · d) / (d · d)


MATH-VEC-REJECT-001

    reject_d(v) = v - proj_d(v)


MATH-VEC-PERP2-001

One canonical perpendicular in XZ:

    perpCCW(x,z) = (-z, x)

Orientation-sensitive code must state whether it expects CW or CCW.

7. SEGMENTS, LINES AND RAYS
======================================================================

MATH-GEO-CLOSEST-SEGMENT-001

Closest point q on segment [a,b] to point p:

    d = b - a
    denom = d · d

    if denom == 0:
        q = a
        t = 0
    else:
        t = clamp(((p-a) · d) / denom, 0, 1)
        q = a + t d

Squared distance:

    ||p-q||²


MATH-GEO-ORIENT2D-001

For planar points a,b,c:

    orient2d(a,b,c)
        = (b_x-a_x)(c_z-a_z)
        - (b_z-a_z)(c_x-a_x)

Interpretation under the canonical XZ orientation:

    > 0 : c lies to the left of directed a -> b
    < 0 : c lies to the right
    = 0 : collinear

Topology-sensitive code must follow NUM-GEO-PREDICATE-001.


MATH-GEO-LINE-INTERSECTION-001

Lines:

    p + t r
    q + u s

Let:

    den = cross2(r,s)

If den != 0:

    t = cross2(q-p, s) / den
    u = cross2(q-p, r) / den

For a closed segment/segment test:

    t ∈ [0,1]
    u ∈ [0,1]

Endpoint policy must be explicit in each algorithm. Road topology commonly
needs separate handling for proper interior crossing versus shared endpoints.


ALG-GEO-SEGMENT-INTERSECTION-001

Pseudocode:

    function intersectSegments(a,b,c,d, endpointPolicy):
        r := b-a
        s := d-c
        den := cross2(r,s)

        if robustZero(den):
            handle collinear/parallel according to endpointPolicy

        t := cross2(c-a, s) / den
        u := cross2(c-a, r) / den

        if endpointPolicy.accepts(t,u):
            return Hit(a + t*r, t, u)

        return NoHit


MATH-GEO-RAY-001

Ray:

    R(t) = O + tD,  t >= 0

D need not be normalized unless a consuming algorithm requires t to represent
metric distance.


ALG-GEO-RAY-TRIANGLE-001

Canonical reference algorithm:

    Möller-Trumbore ray/triangle intersection.

Use barycentric values (u,v):

    u >= 0
    v >= 0
    u + v <= 1

and ray parameter:

    t >= tMin

Reference:

    REF-MOLLER-TRUMBORE-1997

Do not reproduce an ad-hoc plane-test + point-in-triangle implementation in a
hot path unless benchmark/evidence justifies it.

8. POLYGON MATH
======================================================================

MATH-POLY-SIGNED-AREA-001

For ordered planar polygon vertices p_i=(x_i,z_i), i=0..n-1,
with p_n = p_0:

    A_s = 1/2 * Σ_i (x_i z_{i+1} - x_{i+1} z_i)

Absolute area:

    A = |A_s|

Convention:

    positive signed area means CCW under the canonical XZ orientation.


MATH-POLY-CENTROID-001

For a non-degenerate simple polygon:

    cross_i = x_i z_{i+1} - x_{i+1} z_i

    C_x = [1 / (6 A_s)] * Σ_i (x_i + x_{i+1}) cross_i
    C_z = [1 / (6 A_s)] * Σ_i (z_i + z_{i+1}) cross_i

If |A_s| is degenerate, the caller must choose an explicit fallback.
Generic polygon code must not silently pretend the arithmetic mean is the exact
area centroid.


ALG-POLY-POINT-IN-001

For general simple polygons, use a documented winding-number or ray-crossing
implementation.

Boundary classification is a separate state:

    Outside
    Inside
    Boundary

Do not collapse Boundary into Inside/Outside inside the generic primitive.


ALG-GEO-HALFPLANE-CLIP-001

For clipping a polygon against one half-plane, use a
Sutherland-Hodgman-style edge walk:

    for each directed edge prev -> cur:
        prevInside := predicate(prev)
        curInside  := predicate(cur)

        if curInside:
            if !prevInside:
                output(intersection(prev,cur,boundary))
            output(cur)
        else if prevInside:
            output(intersection(prev,cur,boundary))

This algorithm is a natural primitive for:
    Voronoi-like clipping,
    recursive city regions,
    convex clipping stages.


MATH-POLY-COMPACTNESS-001

Isoperimetric compactness:

    Q = 4πA / P²

where:
    A = polygon area
    P = perimeter

For a perfect circle Q=1.
Use only as a heuristic/metric, not a topological validity test.


MATH-POLY-RECTANGULARITY-001

For a raster/cell footprint:

    rectangularity = occupiedArea / boundingRectangleArea

For unit grid cells this reduces to:

    |cells| / (bboxWidthCells * bboxDepthCells)


MATH-POLY-PCA-AXIS-001

For points relative to centroid c:

    dx_i = x_i - c_x
    dz_i = z_i - c_z

Unnormalized covariance terms:

    S_xx = Σ dx_i²
    S_zz = Σ dz_i²
    S_xz = Σ dx_i dz_i

Principal-axis angle:

    θ = 1/2 atan2(2 S_xz, S_xx - S_zz)

This matches the existing procedural-city/building style principal-axis
calculation. Weighting by vertices versus area is a semantic choice and must be
stated by the caller.

9. OBB / SAT
======================================================================

MATH-OBB2-001

2D oriented rectangle:

    center c
    orthonormal axes u,v
    half extents h_u, h_v

A point p is inside when:

    |(p-c) · u| <= h_u
    |(p-c) · v| <= h_v


ALG-SAT-OBB2-001

Two convex OBBs A and B are disjoint if there exists a separating axis among:

    A.u
    A.v
    B.u
    B.v

For each axis n:

    [min_A(n), max_A(n)]
    [min_B(n), max_B(n)]

If intervals do not overlap, the boxes do not overlap.

If no separating axis exists, they overlap.

For 3D box/triangle specialized overlap, see:

    REF-AKENINE-MOLLER-2001

10. CURVES FOR ROADS / PROCEDURAL GEOMETRY
======================================================================

MATH-BEZIER-CUBIC-001

Cubic Bézier curve with control points P0,P1,P2,P3:

    B(t) =
        (1-t)^3 P0
        + 3(1-t)^2 t P1
        + 3(1-t)t^2 P2
        + t^3 P3

for:

    t ∈ [0,1]


MATH-BEZIER-CUBIC-DERIVATIVE-001

    B'(t) =
        3(1-t)^2 (P1-P0)
        + 6(1-t)t (P2-P1)
        + 3t^2 (P3-P2)

Tangent:

    T(t) = normalize(B'(t))

with safe-normalization policy NUM-NORMALIZE-001.


ALG-CURVE-ADAPTIVE-SAMPLE-001

Do not assume equal t steps imply equal world-space spacing.

For collision, road meshing or arc-length-sensitive work:

    recursively subdivide interval [t0,t1]
    compare curve midpoint against chord midpoint
    if geometric error > tolerance:
        subdivide
    else:
        accept chord

Tolerance is expressed in metres and belongs to the consuming chapter.

10A. STABLE NON-CRYPTOGRAPHIC HASHING
======================================================================

MATH-HASH-FNV1A64-001

Canonical FNV-1a 64-bit byte-stream hash for stable small semantic strings and
manual/test identifiers.

Constants:

    offsetBasis = 14695981039346656037
                = 0xcbf29ce484222325

    prime       = 1099511628211
                = 0x00000100000001b3

For each input octet b in order:

    h := h XOR b
    h := (h * prime) mod 2^64

Initial state:

    h := offsetBasis

Known fixtures:

    FNV1a64("")       = 0xcbf29ce484222325
    FNV1a64("a")      = 0xaf63dc4c8601ec8c
    FNV1a64("hello")  = 0xa430d84680aabd0b
    FNV1a64("foobar") = 0x85944171f73967e8

Reference:

    REF-RFC9923-FNV

IMPORTANT:
    FNV is explicitly non-cryptographic.

Use this definition for:
    stable small string/name hashes,
    deterministic fixture IDs where collision risk is acceptable and handled.

Do NOT use it for:
    authentication,
    untrusted collision-resistant hash tables,
    security decisions,
    cryptographic integrity.

A stronger/versioned content hash for persistent artifacts may be introduced by
the serialization/artifact chapters without redefining this ID.


DATA-HASH-CANONICAL-BYTES-001

When a stable semantic hash builder adds typed integers, byte encoding MUST be
explicit rather than native-memory representation.

Canonical integer encoding for the foundation stable hash builder:

    unsigned integer -> little-endian octets of its declared fixed width

For unsigned 64-bit x:

    byte_i = (x >> (8*i)) AND 0xff
    for i = 0..7

Strings in a structured hash builder are length-prefixed:

    addU64(byteLength)
    addBytes(UTF8 bytes)

This prevents concatenation ambiguity such as:

    ["ab", "c"]
    ["a", "bc"]

Raw FNV1a64(string) test-vector function hashes only the string bytes and does
NOT add a length prefix.

Never hash:
    struct padding,
    pointer values,
    native endian raw integer memory,
    unordered-container iteration order

when stable cross-run semantic identity is required.

MATH-RNG-CHILD-SEED-001

Semantic child streams derive from stable labels/IDs:

    childSeed = H(
        parentSeed,
        generatorStableId,

            parent.value,

Forbidden:

    sharedRng.next() from multiple jobs


MATH-SAMPLE-DISK-001

Uniform point in disk radius R:

    u,v ~ Uniform[0,1)

    rho   = R * sqrt(u)
    theta = 2πv

    p = center + rho (cos(theta), sin(theta))

Using rho = R*u is NOT uniform by area.

12. NOISE / FIELDS
======================================================================

MATH-NOISE-FBM-001

Normalized fractal Brownian motion:

    value(x) =
        [Σ_{i=0}^{N-1} a_i N(f_i x)]
        /
        [Σ_{i=0}^{N-1} a_i]

Common recurrence:

    a_{i+1} = gain * a_i
    f_{i+1} = lacunarity * f_i

Parameters are domain-specific and are NOT fixed here.


MATH-NOISE-RIDGED-001

One common ridged transform:

    r = 1 - |N(x)|

Further shaping is domain-specific.


REF-PERLIN-2002 defines the improved gradient-noise interpolation reference used
when native terrain noise is intended to preserve/improve the current Perlin-like
field behavior.

13. GRAPH THEORY / ROUTING
======================================================================

DATA-GRAPH-001

Graph:

    G = (V,E)

Weighted directed or undirected edges have non-negative traversal cost:

    w(e) >= 0

unless a chapter explicitly chooses an algorithm supporting negative edges.


MATH-GRAPH-PATH-COST-001

For path P = (e_1,...,e_k):

    cost(P) = Σ_i w(e_i)


ALG-GRAPH-DIJKSTRA-001

Use Dijkstra for non-negative weighted shortest paths when no useful heuristic
is available.

Core invariant:

    when a node with globally minimum tentative distance is finalized,
    its shortest-path distance is known.


ALG-GRAPH-ASTAR-001

Priority:

    f(n) = g(n) + h(n)

where:

    g(n) = known cost from start to n
    h(n) = estimated cost from n to goal

Canonical relaxation:

    tentative = g(current) + cost(current, neighbor)

    if tentative < g(neighbor):
        cameFrom[neighbor] = current
        g(neighbor) = tentative
        f(neighbor) = tentative + h(neighbor)
        push/update neighbor


MATH-GRAPH-HEURISTIC-001

Admissibility for optimal A*:

    0 <= h(n) <= h*(n)

where h*(n) is the true remaining shortest-path cost.

Consistency/monotonicity:

    h(n) <= c(n,n') + h(n')

for every traversable edge (n,n').

Reference:

    REF-HART-NILSSON-RAPHAEL-1968


ALG-GRAPH-MST-001

For transport skeleton construction, minimum spanning tree means:

    choose acyclic edge set T connecting all required vertices
    minimizing Σ_{e∈T} w(e)

Implementation may use Kruskal or Prim.

Deterministic tie-breaking MUST be defined:

    primary: weight
    secondary: stable edge id


MATH-DELAUNAY-001

For 2D Delaunay triangulation, each triangle satisfies the empty circumcircle
property: no input point lies strictly inside its circumcircle, modulo
degeneracies.

Topological construction must use robust orientation/incircle predicates.

References:

    REF-CGAL-DELAUNAY
    REF-SHEWCHUK-1997


ALG-HALFEDGE-FACE-WALK-001

For a planar embedded graph:

    1. sort outgoing neighbors around each vertex by polar angle,
    2. represent each undirected edge as two directed half-edges,
    3. for directed half-edge u -> v, choose the next half-edge according to
       the fixed face-walk orientation rule at v,
    4. continue until returning to the starting directed half-edge,
    5. mark every traversed directed half-edge visited,
    6. compute signed area,
    7. reject exterior/degenerate faces according to orientation and bounds.

The chosen clockwise/counterclockwise rule MUST be identical in implementation
and tests.

This is the canonical family used for road-graph block extraction.

14. SPATIAL INDEXING
======================================================================

MATH-SPATIAL-GRID-001

For cell size s > 0 and origin o:

    cell_i(p) = floor((p_i - o_i) / s)

Never use integer truncation for negative world coordinates.


ALG-SPATIAL-HASH-001

Object with bounds B is inserted into every overlapped grid cell:

    minCell = floor((B.min - origin)/cellSize)
    maxCell = floor((B.max - origin)/cellSize)

Queries deduplicate object IDs before narrow phase.


ALG-POISSON-BRIDSON-001

Poisson disk sampling in n dimensions, minimum distance r.

Background cell size:

    cellSize <= r / sqrt(n)

Canonical procedure:

    choose initial sample
    add to active list

    while active list not empty:
        choose active sample x
        accepted := false

        repeat up to k attempts:
            candidate := random point in annulus [r, 2r] around x

            if candidate is inside domain
               and no neighboring grid sample is closer than r:
                add candidate
                add candidate to active list
                accepted := true
                break

        if not accepted:
            remove x from active list

Typical paper value:

    k = 30

but production chapter may benchmark/tune it.

Reference:

    REF-BRIDSON-2007


MATH-AABB-001

AABB:

    min = (min_x,min_y,min_z)
    max = (max_x,max_y,max_z)

Union:

    union.min_i = min(A.min_i, B.min_i)
    union.max_i = max(A.max_i, B.max_i)


ALG-RAY-AABB-SLAB-001

For each axis i:

    t0 = (min_i - O_i) / D_i
    t1 = (max_i - O_i) / D_i

Swap if needed so t0 <= t1.

Accumulate:

    tEnter = max(tEnter, t0)
    tExit  = min(tExit,  t1)

No intersection when:

    tEnter > tExit

Zero/near-zero direction components require explicit robust handling.


MATH-BVH-SAH-001

Surface Area Heuristic split estimate:

    C =
        C_traversal
        + (A_L / A_P) * N_L * C_intersect
        + (A_R / A_P) * N_R * C_intersect

where:
    A_P = parent surface area
    A_L/A_R = child surface areas
    N_L/N_R = primitive counts

Treat this as a heuristic cost model, not a correctness rule.

    cos(theta) = (a² + b² - c²) / (2ab)

MATH-QUAT-SLERP-001

For normalized quaternions q0,q1:

    cosOmega = q0 · q1

    q1 := -q1
    cosOmega := -cosOmega

17A. FIXED SIMULATION TIME
======================================================================

MATH-TIME-RATIONAL-TICK-001

For a fixed simulation rate f [ticks/s] and monotonic wall-clock input measured
as integer nanoseconds Δn, Genomes may accumulate wall time without rounding
1/f to an integer nanosecond duration.

Define:

    Q = 1,000,000,000

For each accepted wall delta:

    accumulatorQuanta += Δn * f

One simulation tick is available whenever:

    accumulatorQuanta >= Q

Consume one tick:

    accumulatorQuanta -= Q

Presentation interpolation fraction after all whole ticks are consumed:

    alpha = accumulatorQuanta / Q

with:

    0 <= alpha < 1

This schedules a rational f Hz fixed timestep against integer nanosecond wall
time without repeatedly rounding the duration 1/f to 16,666,667 ns at 60 Hz.

The simulation delta supplied to systems remains conceptually:

    dt = 1/f seconds

Catch-up limits and wall-delta clamping are policy, not part of this equation.

Reference architecture:
    current js/core/fixedClock.js
    REF-FIEDLER-FIXED-TIMESTEP

18. PARALLEL ALGORITHM MODEL
======================================================================

PERF-PAR-WORK-001

Define:

    T1      work / serial execution time
    T∞      critical-path span
    P       processors/workers
    TP      execution time on P workers

For idealized work-stealing analysis of fully strict computations, the classic
bound is of the form:

    E[TP] = O(T1/P + T∞)

Reference:

    REF-BLUMOFE-LEISERSON-1999

This is a design reference, not a promise that the Genomes scheduler will attain
the theoretical bound for arbitrary workloads.


ALG-PAR-STABLE-COMMIT-001

Canonical deterministic parallel pattern:

    partition input by stable semantic ranges

    parallel_for partition:
        process only owned range
        write thread/job-local output

    barrier

    concatenate outputs

    stable_sort by semantic stable key if production order matters

    deterministic commit

Do not use worker completion order as semantic order.


ALG-PAR-REDUCE-001

Floating reductions are not generally bitwise associative.

If bitwise deterministic result is required:

    - use fixed partitioning and fixed reduction tree,
    - or use an exact/fixed-point representation where appropriate,
    - or explicitly accept bounded non-bitwise determinism.

A chapter must state which level it requires.

ALG-BUILD-CANDIDATE-SOLVER-001

Generic bounded candidate-search pattern:

    best := none
    bestScore := +infinity

    for candidate in deterministicCandidateOrder:
        if !hardConstraints(candidate):
            continue

        score := objective(candidate)

        if score < bestScore
           or (score == bestScore and candidate.stableId < best.stableId):
            best = candidate
            bestScore = score

    return best

Rules:
    hard constraints are not soft penalties,
    tie-breaking is deterministic,
    solver budget is explicit,
    exhausted budget returns typed failure/fallback rather than undefined state.

ALG-RNG-MULBERRY32-LEGACY-001

SOURCE family references:
    SOURCE::js/core/seededRandom.js
    SOURCE::js/buildings/buildingRandom.js
    SOURCE::prototypes/procedural-city/index.html

The output mixer is the Mulberry32 family, but SOURCE has small state-storage
differences that MUST be distinguished for exact compatibility:

A. LegacyCoreSeededRandomJS
   SOURCE::js/core/seededRandom.js

    state is a JavaScript Number initialized with seed >>> 0.

    next():
        state = state + 0x6D2B79F5      // no explicit uint32 assignment
        t = ToInt32(state) for bitwise operations
        t = imul(t XOR (t >>> 15), t OR 1)
        t = t XOR [t + imul(t XOR (t >>> 7), t OR 61)]
        u = uint32(t XOR (t >>> 14))
        return u / 2^32

   For ordinary generator stream lengths below JavaScript integer precision
   limits, this produces the same low-32-bit sequence as uint32 wrapping.
   An EXACT adapter claiming arbitrary-length JS parity should model the
   JavaScript Number/ToInt32 semantics rather than silently assuming uint32
   state forever.

B. LegacyBuildingMulberry32
   SOURCE::js/buildings/buildingRandom.js

    state := uint32(seed)
    each next explicitly:
        state := uint32(state + 0x6D2B79F5)
    then applies the same mixer.

C. LegacyCityMulberry32
   SOURCE::prototypes/procedural-city/index.html

    a := uint32(seed)
    each next begins:
        a := ToInt32(a)
        a := ToInt32(a + 0x6D2B79F5)
    then applies the equivalent mixer.

and adapter family. Do not use the generic label "LegacyMulberry32" alone when

    h := uint32(imul(h XOR (h >>> 16), 0x7feb352d))
    h := uint32(imul(h XOR (h >>> 15), 0x846ca68b))
    h := uint32(h XOR (h >>> 16))
    return h
