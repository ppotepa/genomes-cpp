======================================================================
PUBLIC CONTRACTS
======================================================================
1. Core count policy depends on floors, gross area, use/program and egress requirements; zero allowed for single-storey.

2. CoreCandidate is axis-aligned/local-grid rectangle or oriented rectangle fully contained on all served storeys, with dimensions sufficient for selected stair layout.

3. Hard constraints include containment, overlap, minimum clearance/headroom recipe, vertical alignment and no conflict with reserved structural/exterior zones.

4. Objectives include average path distance proxy, center/edge preference by program, symmetry, long-axis distribution and separation among multiple cores.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define StairProfile with minWidth, landingDepth, maxRiser, minTread, headroom, flight model; values are data and building-code profile specific, not universal constants.

STEP 2
    Enumerate candidate rectangles efficiently using 2D prefix occupancy from footprint.

STEP 3
    Score one-core candidates using sampled footprint graph-median proxy and symmetry/edge penalties.

STEP 4
    For multiple cores derive target fractions along long axis and choose non-overlapping candidates with separation objective.

STEP 5
    Generate StairRecipe from floor-to-floor height: select integer riser count satisfying max riser and tread/run envelope; fail/fallback if impossible.

STEP 6
    Validate every served floor opening/landing alignment.

======================================================================
PSEUDOCODE
======================================================================
STAIR DIMENSIONS:
    for riserCount in feasible integer range:
        riser := floorHeight / riserCount
        if riser > profile.maxRiser: continue
        tread := choose >= minTread fitting available run
        score comfort/run/landing
    choose best deterministic

CORE:
    candidates := contained rectangles prefix-summed
    if count==1: choose min objective
    else:
        targets := fractions along long axis
        sequential bounded selection with nonoverlap + separation
    return cores + stair recipes

THREADING / OWNERSHIP RULES
======================================================================
One BuildingPlan candidate is owned by one job until frozen. Batch jobs are independent by BuildingId/SeedPath and merge in stable ID order.

======================================================================
ERROR HANDLING
======================================================================
Bounded solvers return typed failure/fallback reasons and ValidationReport. Invalid building candidates are never partially committed.

DETERMINISM RULES
======================================================================

PERFORMANCE RULES
