======================================================================
PUBLIC CONTRACTS
======================================================================
1. Entrance candidates come from exposed exterior segments and road/front metadata. Main/service/secondary entrances are stable semantic objects.

2. Circulation cells/polylines connect required terminals (entrances, cores, major program anchors) and are reserved before room subdivision.

3. Room program defines target/min/max area, adjacency preferences/requirements, exterior daylight/frontage preference, service/core proximity and count.

4. Hard constraints (connectivity, minimum dimensions, access) are never converted to soft score penalties. Solver has explicit iteration/branch budget and fallback.

======================================================================
DATA LAYOUT
======================================================================
Building semantic data uses stable IDs, compact arrays and polygons/cells. Render/physics/nav representations are separate compiler outputs.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Find entrance candidates from exterior boundary and road-facing metadata; select main then diversity/separation-based secondary/service.

STEP 2
    Create walkable/reservable solver grid excluding core cells; choose circulation hub and connect required terminals with A* cost favoring low bends/centrality and away from exterior where appropriate.

STEP 3
    Widen centerlines to corridor band based on program profile while preserving room area.

STEP 4
    Build initial free-space regions and recursively split/assign RoomProgram slots using macro axes and frontage.

STEP 5
    Construct room adjacency graph from shared boundaries and corridor contacts.

STEP 6
    Run repair passes bounded: merge undersized spaces, adjust cuts, reassign program; validate all occupied spaces reachable from entrance/core network.

STEP 7
    Emit failure trace with unsatisfied constraints.

======================================================================
PSEUDOCODE
======================================================================
CIRCULATION:
    terminals := entrances + core landings + anchors
    hub := choose central accessible cell
    for t in stable terminal order:
        path := A*(freeCells,t,hub,cost=bends+axis+edge)
        reserve widen(path)

ROOMS:
    free := footprint - cores - circulation
    candidateSpaces := recursiveSplit(free, macro priors)
    assignment := solveProgram(candidateSpaces, requirements)
    for bounded repair:
        fix undersize/disconnected/adjacency
    validate reachability + areas + access

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
One BuildingPlan candidate is owned by one job until frozen. Batch jobs are independent by BuildingId/SeedPath and merge in stable ID order.

======================================================================
ERROR HANDLING
======================================================================
Bounded solvers return typed failure/fallback reasons and ValidationReport. Invalid building candidates are never partially committed.

======================================================================
DETERMINISM RULES
======================================================================
Candidate order, tie-breaking and RNG streams are stable by semantic IDs. Worker count and hash-map iteration do not affect the plan.

======================================================================
PERFORMANCE RULES
======================================================================
Use bounded candidate sets, spatial/prefix structures and scratch arenas. No unbounded backtracking. Batch independent buildings over JobSystem.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET constraints and quality metrics define behavior. Prototypes contribute
scenarios only and cannot select alternate solver algorithms.
