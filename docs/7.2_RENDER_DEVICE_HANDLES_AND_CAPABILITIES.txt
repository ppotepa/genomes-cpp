======================================================================
PUBLIC CONTRACTS
======================================================================
1. BufferHandle/TextureHandle/SamplerHandle/PipelineHandle use generational handles; stale handle access fails diagnostics in development and typed error in public lookup.

2. RenderCapabilities explicitly reports backend, API version, bindless/resource indexing, compute, async compute queue availability, indirect draw, mesh shaders, ray tracing, timestamp queries, limits/alignment.

3. Resource descriptors are Genomes types with usage/bind flags; Diligent translation is centralized.

4. Resource destruction is deferred until GPU fence/frame retirement guarantees no in-flight use.

======================================================================
DATA LAYOUT
======================================================================
Public renderer-facing handles are compact generational values. Backend objects are private implementation data.

======================================================================
PSEUDOCODE
======================================================================
CREATE BUFFER:
    slot := pool.acquire()
    native := diligent.createBuffer(translate(desc))
    slot.generation += reusePolicy
    slot.native = native
    return BufferHandle(slot.index,slot.generation)

DESTROY(handle):
    slot := validate(handle)
    enqueueDeferredRelease(slot.native,currentFence)
    invalidate slot generation

RETIRE:
    while queue.front.fence <= completedFence:
        release native
        recycle slot

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Render backend owns GPU objects. Simulation never touches Diligent objects. Render extraction consumes immutable snapshots and stages uploads.

======================================================================
ERROR HANDLING
======================================================================
Device/shader/resource failures return typed errors with diagnostics; no silent fallback that changes correctness or feature policy.

======================================================================
DETERMINISM RULES
======================================================================
Presentation may be frame-order nondeterministic, but stable semantic IDs map to persistent GPU records; no render result feeds authoritative gameplay unless explicitly specified.

======================================================================
PERFORMANCE RULES
======================================================================
Minimize CPU submission, resource churn, state changes and readbacks. All GPU features are capability/benchmark driven.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Three.js SOURCE remains visual/reference evidence; native renderer does not attempt API parity with Three.js.
