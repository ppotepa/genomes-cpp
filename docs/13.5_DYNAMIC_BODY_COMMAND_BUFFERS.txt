======================================================================
PUBLIC CONTRACTS
======================================================================
1. Command phases: PreStep structural (create/destroy/shape/layer), PreStep motion (kinematic target/velocity/impulse), PostStep safe extraction/events. Conflicting commands on same handle use stable sequence/priority policy.

2. Dynamic body table maps PhysicsBodyHandle <-> Jolt BodyID + semantic Entity/Structural ID; table changes only on physics owner.

3. Kinematic position target is explicit; teleport vs kinematic move are distinct commands.

4. Snapshot extracts only active/changed bodies into SoA transform/velocity records for simulation/presentation.

======================================================================
DATA LAYOUT
======================================================================
Public physics handles/recipes are Genomes-owned. Jolt BodyID/ShapeRef are backend-private mappings.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Implement thread-local PhysicsCommandBuffer and merge by phase + body stable handle + sequence.

STEP 2
    Validate command target generation before applying; stale commands report/drop by policy.

STEP 3
    Batch Jolt BodyInterface operations where API supports batch add/activate.

STEP 4
    Implement contact/activation callback event queues using lock-free/MPSC or per-thread buffers; copy data, no mutation.

STEP 5
    Extract changed active body transforms after Update into PhysicsSnapshot.

STEP 6
    Benchmark 1k/10k/100k sleeping vs active bodies and command volumes.

======================================================================
PSEUDOCODE
======================================================================
MERGE COMMANDS:
    gather local buffers
    stable sort conflicting key=(phase,body,sourceSequence)
    coalesce:
        last SetVelocity wins by defined priority
        impulses accumulate in defined order or vector sum policy
        Destroy suppresses later commands

STEP:
    apply structural
    apply motion
    Jolt Update
    drain callback buffers
    extract active transforms

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Producers never touch Jolt. Physics owner applies. Callbacks only append thread-local events; no world mutation.

======================================================================
ERROR HANDLING
======================================================================
Backend errors map to typed PhysicsError/diagnostics. Failed body creation or step does not leave half-registered public handles.

======================================================================
DETERMINISM RULES
======================================================================
Conflicting command resolution specified; Jolt internal contact ordering not exposed as semantic order.

======================================================================
PERFORMANCE RULES
======================================================================
Batch BodyInterface calls, active-body-only snapshot, no per-body heap allocation.
