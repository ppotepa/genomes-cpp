======================================================================
PUBLIC CONTRACTS
======================================================================
1. Equipment data is not genome. For SOURCE equipment schema v1, exact
compatibility seed derivation is ALG-RNG-EQUIPMENT-HASH32-001:

    equipmentSeed = hash(unitSeed, "EQUIPMENT/v1")
    slot choice seed = hash(equipmentSeed, "slot/" + slot)
    item variant seed = hash(equipmentSeed, slot + "/" + definitionId)

The resulting random draws use LegacyMulberry32. A canonical native SeedTree
replacement is allowed only under a new Equipment seed/schema version.

2. Equipment catalog/loadouts are immutable data. Overrides explicitly replace profile slots, including null for optional empty. Required clothing null resolves documented base layer policy.

3. EquipmentFit derives attachment/fitting from final phenotype/surface/skeleton landmarks in bind space. Dimensions are metres or normalized once; no double scaling.

4. Gear geometry is backend-neutral skinned MeshData using the same SkeletonData as body. No gear-specific skeleton.

5. Changing equipment must preserve locomotion/face/blink phase and biological identity; rebuilding appearance only where clothing/occlusion dependency requires it.

======================================================================
DATA LAYOUT

PSEUDOCODE
======================================================================
RESOLVE EQUIPMENT - SOURCE SCHEMA V1:
    equipmentSeed := LegacyEquipmentHash32(unitSeed, "EQUIPMENT/v1")
    slots := profile.defaults

    for slot in SOURCE slotSchema enumeration order:
        choiceSeed := LegacyEquipmentHash32(equipmentSeed, "slot/" + slot)
        choiceRng := LegacyMulberry32(choiceSeed)
        choose profile alternative if array

        if override exists:
            item := override.value  // may be null

        if item:
            itemSeed :=
                LegacyEquipmentHash32(
                    equipmentSeed,
                    slot + "/" + item.definitionId
                )

            variantRng := LegacyMulberry32(itemSeed)
            variant.size   := .965 + variantRng.next()*.07
            variant.shade  := .92  + variantRng.next()*.13
            variant.detail := variantRng.next()

            validate item allowed in slot

A future native schema may canonicalize slot iteration and derive semantic child
streams, but that change requires a new equipment seed/schema version.

FIT ITEM:
    bindPoint := fit.semanticPoint(item.kind, slot, phenotype, skeleton)
    recipe := generator(item.definition.visual, variant, fit)
    skin recipe to existing BoneIndices
    return recipe

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Resolve/geometry generation pure per equipment state. Catalog immutable. Gear artifact cache keyed by phenotype+equipment+generator versions. Runtime changes commit at safe entity/presentation phase.

======================================================================
ERROR HANDLING
======================================================================
Unknown ID/incompatible slot/nonfinite seed/options -> explicit error before commit. Candidate equipment/artifact built+validated before replacing active state.

======================================================================
DETERMINISM RULES
======================================================================
For exact SOURCE schema v1, preserve EquipmentHash32 and the observed slot
resolution semantics. Item variant seed is isolated by slot+definition, so
unrelated item variants do not reroll each other.

A later native schema may strengthen slot-order independence with canonical
slot ordering/SeedPath, but must use a new version. Side palette color does not
alter item identity seed.

======================================================================
PERFORMANCE RULES
======================================================================
Build only spawn/change/detail transition. Shared materials; merge gear where compatible. No per-buckle scene object. Cache identical resolved state.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Preserve catalog IDs/loadouts from SOURCE and fixture exactness where gameplay data. Visual shape invariant/visual parity, not Three.js buffers.
