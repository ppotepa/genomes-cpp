======================================================================
PUBLIC CONTRACTS
======================================================================
1. Equipment data is not genome. Equipment identity uses named SeedPath streams:

    equipment root = SeedTree(unitSeed).child("equipment")
    slot choice     = root.child("slot", canonicalSlotId).child("choice")
    item variant    = root.child("slot", canonicalSlotId)
                          .child("item", definitionId)

Canonical slot IDs, not array/hash iteration order, define identity.

2. Equipment catalog/loadouts are immutable data. Overrides explicitly replace profile slots, including null for optional empty. Required clothing null resolves documented base layer policy.

3. EquipmentFit derives attachment/fitting from final phenotype/surface/skeleton landmarks in bind space. Dimensions are metres or normalized once; no double scaling.

4. Gear geometry is backend-neutral skinned MeshData using the same SkeletonData as body. No gear-specific skeleton.

5. Changing equipment must preserve locomotion/face/blink phase and biological identity; rebuilding appearance only where clothing/occlusion dependency requires it.

======================================================================
DATA LAYOUT
======================================================================
EquipmentState: seed, loadoutId optional, canonical slot array, override mask, palette, wear, totalWeight, revision. ItemInstance: definitionId, slotId, stable seed, compact variant{size,shade,detail}.

PSEUDOCODE
======================================================================
RESOLVE EQUIPMENT:
    equipmentRoot := SeedTree(unitSeed).child("equipment")
    slots := profile.defaults

    for slot in canonical EquipmentSlot order:
        choiceRng := equipmentRoot.child("slot",slot.id).child("choice").rng()
        choose profile alternative if array

        if override exists:
            item := override.value  // may be null

        if item:
            variantRng := equipmentRoot.child("slot",slot.id)
                                       .child("item",item.definitionId).rng()
            variant.size   := .965 + variantRng.next()*.07
            variant.shade  := .92  + variantRng.next()*.13
            variant.detail := variantRng.next()

            validate item allowed in slot

FIT ITEM:
    bindPoint := fit.semanticPoint(item.kind, slot, phenotype, skeleton)
    recipe := generator(item.definition.visual, variant, fit)
    skin recipe to existing BoneIndices
    return recipe

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Resolve/geometry generation pure per equipment state. Catalog immutable. Gear artifact cache keyed by phenotype+equipment+generator versions. Runtime changes commit at safe entity/presentation phase.

======================================================================
ERROR HANDLING
======================================================================
Unknown ID/incompatible slot/nonfinite seed/options -> explicit error before commit. Candidate equipment/artifact built+validated before replacing active state.

======================================================================
DETERMINISM RULES
======================================================================
Equipment resolution uses canonical slot ordering and named SeedPath streams.
Item variant identity is isolated by slot + definition, so unrelated items do
not reroll one another. Side palette color does not alter item identity seed.

======================================================================
PERFORMANCE RULES
======================================================================
Build only spawn/change/detail transition. Shared materials; merge gear where compatible. No per-buckle scene object. Cache identical resolved state.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET catalog IDs/loadouts and fitting invariants define behavior. Imported
catalog samples and images are diagnostic only, never Three.js buffer contracts.
