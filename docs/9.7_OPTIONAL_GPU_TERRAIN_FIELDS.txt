======================================================================
PUBLIC CONTRACTS
======================================================================
1. GPU kernels may accelerate noise grid, slope/normal, simple raster masks/distance transforms where algorithm is data-parallel; topology/graph stages stay CPU.

2. Generator execution policy selects CPU/GPU based on size/capabilities/benchmark threshold. RequireGpu only tooling/experiment option.

3. GPU float result parity uses explicit tolerances and generator backend metadata; if semantic exact cross-platform artifact identity is required, CPU path is used or quantization canonicalization defined.

4. Best path keeps intermediate fields GPU-resident when downstream GPU compiler consumes them; avoid roundtrip solely to immediately upload again.

IMPLEMENTATION STEPS

STEP 2
    Implement noise kernel only after matching chosen numeric contract; do not claim exact legacy JS parity if transcendental/float differences exist.

STEP 3
    Use ComputeBenchmarkHarness to find crossover sizes including transfers.

STEP 4
    Record backend in artifact derivation metadata if output may differ numerically beyond exact fingerprint.

STEP 5
    Add policy Auto threshold table default conservative; runtime profiling may override locally without changing semantic version policy.

======================================================================
PSEUDOCODE
======================================================================
GENERATE FIELD:
    if policy == CPU: return cpu()
    if gpuAvailable and size >= crossover and parityModeAllowsGpu:
        gpuResult := dispatch kernels
        if downstream needs CPU semantic artifact:
            async readback then canonicalize/validate
        else retain GPU derived representation + CPU required semantic subset
    else:
        cpu()
