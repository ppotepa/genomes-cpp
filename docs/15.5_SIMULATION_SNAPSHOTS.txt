======================================================================
PUBLIC CONTRACTS
======================================================================
1. SimulationSnapshot is not full ECS clone by default. It is immutable published view/package of selected components/state revisions needed by consumers (render, replay/hash, async queries).

2. Hot transform interpolation stores previous/current transform or sample pair per relevant entity, updated at fixed tick commit; render computes alpha separately.

3. Snapshot has SimulationTick, world/ecs revision, region origin/rebase revision and stable entity presentation records.

4. Replay/checksum snapshot uses separate canonical serialization of authoritative components, not presentation record hash.

======================================================================
DATA LAYOUT
======================================================================
Authoritative mutable simulation state remains in ECS/world databases.

Published snapshot is immutable and contains only fields required by consumers:
    stable EntityId
    transforms/velocities
    presentation state/LOD inputs
    selected semantic world revisions
    event ranges
    optional pose/skeleton channel handles

Use double/triple buffered SnapshotStorage with generation/revision. Writers
publish only after fixed-tick barrier; readers hold a snapshot generation until
release. Snapshot arrays are contiguous/SoA where consumers benefit.

PSEUDOCODE
======================================================================
TICK BEGIN:
    for transform dirty last tick:
        previous := current

SYSTEMS/PHYSICS update current

COMMIT:
    apply commands
    build dirty presentation records
    publish snapshot(tick,current,previous)

STATE HASH:
    entities := stable sort semantic IDs
    serialize selected authoritative components canonical
    contentHash

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Snapshot building reads committed state. Published data immutable; renderer never reads live ECS.

======================================================================
ERROR HANDLING
======================================================================
Invalid/stale entity handles and illegal structural mutation return typed errors or development assertions; expected gameplay failures are not exceptions.

======================================================================
DETERMINISM RULES
======================================================================
Authoritative hash stable order/canonical bytes; presentation interpolation not authoritative.

PERFORMANCE RULES
