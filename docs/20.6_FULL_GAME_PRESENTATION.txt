======================================================================
PUBLIC CONTRACTS
======================================================================
1. Presentation consumes immutable PresentationSnapshot and GPUScene databases; it never mutates authoritative world/entities.

2. Render quality controls framebuffer/shadow/LOD/presentation budgets only, not procedural semantic identity or combat outcomes.

3. GPU Scene handles terrain chunks, road/driveway corridors, parcel fence/gate
instance pages, building representations, vegetation instance pages, dynamic
entity instances/skeletons and debris/rubble with independent LOD/visibility.

4. Combat/destruction presentation is event-driven and may drop/coalesce purely visual effects under budget without dropping semantic events.

5. Debug overlays/traces are separate passes/resources and can be disabled with zero semantic cost.

======================================================================
DATA LAYOUT
======================================================================
PresentationSnapshot references stable RenderEntityId/GPU asset handles/transforms/skeleton channels/events. GPU Scene persistent arrays; per-frame upload delta buffers/frame arenas.

    graph.reset()
    graph.add(depth)

    graph.add(post)
    graph.compile(capabilities)

THREADING / OWNERSHIP RULES
======================================================================
Render graph/resource preparation follows Diligent/render threading policy. Simulation snapshot immutable; async compute only via Stage 8 contracts.

======================================================================
ERROR HANDLING
======================================================================
Missing render artifact uses explicit placeholder/hidden presentation with diagnostic; semantic entity remains. GPU device loss handling deferred production chapter but no world corruption.
