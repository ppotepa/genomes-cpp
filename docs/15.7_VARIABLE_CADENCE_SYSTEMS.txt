======================================================================
PUBLIC CONTRACTS
======================================================================
1. CadencePolicy = EveryTick, EveryNTicks, FrequencyHz mapped to integer tick pattern, AdaptiveTier selected by semantic activity/distance/visibility policy. Tick skipping never pauses entity's world time.

2. Per-entity/system due scheduling uses nextDueTick/phase bucket, not accumulating float dt.

3. Camera visibility may affect presentation cadence; authoritative tactical simulation cadence may use relevance/activity but cannot make outcomes camera-dependent unless explicitly nonauthoritative.

4. When a low-rate system runs, elapsedTicks since last run is passed so timers/integration can advance correctly or system uses event timestamps.

======================================================================
DATA LAYOUT
======================================================================
CadencePolicy is compact value data:
    kind {EveryTick, EveryNTicks, RationalFrequency, AdaptiveTier}
    period numerator/denominator or periodTicks
    stable phase offset
    minimum/maximum tier limits

Per system/entity cadence state:
    lastRunTick
    nextDueTick or derived bucket
    current authoritative relevance tier
    optional presentation tier stored separately

Due buckets are arrays/ranges keyed by tick modulo period where practical.
Camera-derived presentation cadence is never stored in authoritative tactical
relevance state.

======================================================================
PSEUDOCODE
======================================================================
DUE:
    period := cadence.periodTicks
    phase := stableHash(entityId) % period
    return (tick % period) == phase

RUN:
    elapsed := tick - state.lastRunTick
    system.update(entity, elapsedTicks=elapsed)
    state.lastRunTick := tick

TIER:
    if inCombat: period=1 or tactical configured
    else if activeRegion: period=6
    else dormant: period=30/aggregate
