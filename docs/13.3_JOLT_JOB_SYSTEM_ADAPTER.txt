CHAPTER 13.3 - JOLT_JOB_SYSTEM_ADAPTER
STATUS: READY

======================================================================
GOAL
======================================================================
Implement Jolt JobSystem adapter over Genomes JobSystem so Jolt simulation jobs use the shared worker pool while respecting Jolt barrier/wait semantics and avoiding deadlocks.

======================================================================
PUBLIC CONTRACTS
======================================================================
1. Adapter implements JPH::JobSystem CreateJob/QueueJob(s)/FreeJob/GetMaxConcurrency and barrier behavior required by pinned Jolt version.

2. Jolt dependency tracking remains Jolt-owned. QueueJob maps ready Jolt job into Genomes JobSystem runnable without duplicating dependency logic.

3. WaitForJobs/barrier must follow Jolt semantics; while PhysicsSystem::Update owns update, no unrelated gameplay job may call into/mutate PhysicsSystem and deadlock on body locks.

4. Jolt job wrapper lifetime extends until Jolt releases job; allocation uses dedicated bounded pool/arena suitable for max job count.

======================================================================
DATA LAYOUT

Public physics handles/recipes are Genomes-owned. Jolt BodyID/ShapeRef are backend-private mappings.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Read exact pinned Jolt JobSystem API and copy only interface-required barrier logic where license allows, documenting provenance.

STEP 2
    Map CreateJob function/name/color/dependency count into Jolt Job object + Genomes scheduling wrapper.

STEP 3
    QueueJob(s) submit immediately runnable job to shared JobSystem with physics profiling tag/priority.

STEP 4
    Implement WaitForJobs using Jolt barrier rule; do not let waiting thread execute arbitrary jobs that may interact with PhysicsSystem if unsafe. Provide physics-scoped assist queue/filter if necessary.

STEP 5
    Stress nested Jolt jobs through PhysicsSystem::Update at 1..N workers.

STEP 6
    Benchmark Jolt stock thread pool vs adapter for representative body/contact counts; production chooses adapter if correctness passes, not solely speed.

======================================================================
PSEUDOCODE
======================================================================
QUEUE JOLT JOB:
    genomesJobs.submit(tag=Physics, fn:
        joltJob.Execute()
        // Jolt Job handles its dependency completion/reference lifecycle
    )

WAIT BARRIER:
    while barrier not complete:
        execute ONLY jobs admitted by physics barrier/adapter safe set
        or block on barrier condition
    return

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Physics Update caller owns step. Jolt callbacks occur on worker threads; callbacks copy events only. No body add/remove from contact callback.

======================================================================
ERROR HANDLING
======================================================================
Backend errors map to typed PhysicsError/diagnostics. Failed body creation or step does not leave half-registered public handles.

======================================================================
DETERMINISM RULES
======================================================================
Adapter scheduling order is nonsemantic. Contact/event publication sorted/stabilized later only when domain semantics require.

======================================================================
PERFORMANCE RULES
======================================================================
Use pooled job wrappers, batch QueueJobs, measure oversubscription = none because shared worker pool.

======================================================================
MIGRATION / COMPATIBILITY
