======================================================================
PUBLIC CONTRACTS
======================================================================
1. GameApplication is composition root only: creates EngineServices, registers domain modules and owns lifecycle. Domain systems do not reach back into application singleton.

2. WorldScenario/WorldSpec selects seed/size/profile/module options then invokes GenerationGraph -> RegionPackages -> World commit. No renderer-owned world objects.

3. Initialization order: foundation/jobs/assets -> world/proc -> physics/nav -> render (if graphical) -> domain modules -> scenario. Shutdown reverses ownership safely after jobs drain.

4. Headless and graphical applications share semantic world/simulation assembly; graphical mode adds presentation/render extraction only.

5. World creation is transactional: old active world remains until new candidate generation/compile succeeds; cancellation cleans candidate resources.

6. World GenerationGraph makes the cross-module dependency explicit:
terrain/hydrology -> roads -> regions/zoning -> blocks -> parcels/buildable ->
BuildingSiteRequests -> BuildingSpecs -> BuildingPlans +
BuildingSiteResolutions -> finalized access/fences/reservations -> vegetation ->
region database/packages -> representation compilers. A city placeholder is
never committed as a final building.

======================================================================
DATA LAYOUT
======================================================================
Application owns service instances by explicit unique ownership. ActiveWorldHandle points to committed World database. Scenario config is serializable semantic data.

PSEUDOCODE
======================================================================
BOOT:
    jobs := JobSystem(config.workers)
    assets/artifacts := ArtifactStore(...)
    proc := ProceduralService(jobs, artifacts)
    world := WorldService(proc,jobs)
    physics := PhysicsService(jobs)
    nav := NavigationService(jobs,world)
    simulation := SimulationService(jobs,world,physics,nav)
    if graphical: render := RenderService(...)
    modules.register(Terrain,City,Buildings,Vegetation,Destruction,Ballistics,Infantry,Weapons,Combat)

START_NEW(spec):
    cancel previous candidate
    tx := GenerationTransaction()
    artifacts := proc.generateWorld(spec,tx)
    validate all
    compile region packages in parallel
    candidate := world.createCandidate(packages)
    candidate.initPhysicsNav()
    if graphical: candidate.preparePresentation()
    world.commit(candidate)
    retire old world after readers release snapshot

FRAME:
    alpha := fixedClock.advance(now, simulation.fixedTick)
    snapshot := simulation.presentation(alpha)
    render?.frame(snapshot)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Composition root controls service lifetime; generation uses JobSystem groups/cancellation. Simulation/render synchronize via immutable snapshots. No app mutex around whole frame.

======================================================================
ERROR HANDLING
======================================================================
Any generation/compile/init failure aborts candidate and keeps previous world. Fatal initialization errors reported before main loop with subsystem context.

======================================================================
DETERMINISM RULES
======================================================================
World semantic generation/ticks independent of render/headless mode and worker schedule per prior gates.

======================================================================
PERFORMANCE RULES
======================================================================
Lazy startup creates no world until requested. Track phase timings/generation peak memory. No duplicate semantic world for renderer.

======================================================================
MIGRATION / COMPATIBILITY

This chapter assembles the production architecture. Reference scenarios in 20.2
validate coverage but do not gate the shape of runtime APIs.
