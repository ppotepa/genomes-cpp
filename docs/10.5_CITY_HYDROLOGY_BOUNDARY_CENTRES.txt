======================================================================
PUBLIC CONTRACTS
======================================================================
1. CitySpec includes target area, settlement scale, morphology, density, terrain weight, rural fringe, polycentricity, plannedness, hydrology mode and seed.

2. Boundary is semantic Polygon2 approximating target area and respecting terrain/water constraints; boundary-area error has explicit acceptance threshold by city scale.

3. Centers have stable IDs, strength/radius/mass/role. Main center not required to be world origin; secondary centers obey spacing/water/slope rules.

4. Gateways lie on/near boundary and represent external transport connections; count/directions derive from scale/morphology/seed.

IMPLEMENTATION STEPS
======================================================================
STEP 1
    Define CityProfile presets as data assets/constants with versioning; user modifiers apply to cloned normalized profile.

STEP 2
    Generate center candidates with deterministic separation and terrain/hydrology validation.

STEP 3
    Solve boundary radius/shape iteratively to target area using field sampling, with max iterations and fallback report.

STEP 4
    Classify river-city relation None/Through/Adjacent/External from boundary/water overlap.

STEP 5
    Generate gateways distributed by external attraction/axes and validate inside/outside crossing semantics.

STEP 6
    Export golden seeds across hamlet/village/town/city/metropolis and hydrology relations.

PSEUDOCODE
======================================================================
BOUNDARY SOLVE:
    shapeParams := seed children
    lo,hi := radius bounds
    repeat maxIterations:
        r := midpoint(lo,hi)
        poly := sampleBoundary(r,terrainInfluence,noise)
        area := abs(area(poly))
        if area < target: lo=r else hi=r
    validate simple polygon + area error
    return best

CENTRES:
    add main valid candidate
    for desired secondary:
        sample semantic candidates
        accept if slope/water/spacing
        assign stable CenterId

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Each generation stage reads immutable prior artifacts and writes a candidate output; independent regions/blocks/parcels use jobs with stable IDs and stable merge.

======================================================================
ERROR HANDLING
======================================================================
Invalid candidates are rejected through typed result/ValidationReport; bounded fallback strategies are explicit and traced.

======================================================================
DETERMINISM RULES
======================================================================
Stable seed paths, node/edge IDs and deterministic tie-breakers define output; hash-map/job iteration never does.

======================================================================
PERFORMANCE RULES
======================================================================
Use spatial indexes/fields rather than global scans; batch expensive routing/placement and benchmark large city profiles.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
TARGET contracts and validators are authoritative. Prototype scenes are
optional diagnostic inputs and never select alternate algorithms.
