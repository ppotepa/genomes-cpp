======================================================================
PUBLIC CONTRACTS
======================================================================
1. Streaming target is a desired residency vector, not loaded bool: Semantic, Render, Physics, Navigation, SimulationActive.

2. Request priority derives from gameplay need/camera/distance but stable correctness does not depend on completion order.

3. Each region load has generation token; stale completion from cancelled/replaced request is discarded.

4. Budgets are explicit bytes/counts and eviction chooses eligible Dormant/nonpinned regions; active combat/objective pins may block eviction.

======================================================================
DATA LAYOUT
======================================================================
Use explicit versioned value types and ownership. Hot data remains contiguous; cold metadata is separate.

IMPLEMENTATION STEPS

STEP 2

STEP 3

STEP 4

STEP 6

======================================================================
PSEUDOCODE
======================================================================
REQUEST(id, desired):
    gen := ++record.streamingGeneration
    cancel old group
    group := new JobGroup
    if need semantic:
        spawn load/generate semantic
    after semantic:
        spawn renderCompiler if desired.render
        spawn physicsCompiler if desired.physics
        spawn navCompiler if desired.nav

COMPLETE(result, gen):
    if gen != record.streamingGeneration:
        discard result
    else commit representation
