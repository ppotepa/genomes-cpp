PUBLIC CONTRACTS
======================================================================
1. Door openings connect adjacent spaces or exterior entrance and align with circulation; every required adjacency/access edge maps to at least one passable opening.

2. Window placement depends on exterior wall runs, room use/daylight target, structural margins and spacing. Windows never span corners/doors/cores blindly.

3. Stair semantic recipe from 11.4 creates slab openings, flights/landings and rail/headroom clearance metadata.

4. RoofPlan is semantic surfaces/ridges/valleys/eaves by footprint decomposition and RoofFamily constraints; geometry compiler comes later.

======================================================================
IMPLEMENTATION STEPS
======================================================================
STEP 1
    Extract wall runs from room/exterior topology with stable WallRunId.

STEP 2
    Place required doors first: entrance, room-corridor, required room adjacency; choose location maximizing clearance from corners/other openings.

STEP 3
    Place optional doors only after graph connectivity validation.

STEP 4
    Place windows per room exterior run using target window-to-wall range/profile and stable spacing; validate lintel/sill and structural reserved zones.

STEP 5
    Create floor slab voids matching stair/core recipes and verify headroom swept volumes.

STEP 6
    Generate roof candidate family Flat/Gable/Hip/Shed/composed by macro footprint; solve ridge axis from principal/macro axes and drainage; validate no inverted/self-intersecting roof surfaces.

STEP 7
    Emit RoofPlan surfaces with slope plane equations/adjacency.

======================================================================
PSEUDOCODE
======================================================================
DOORS:
    for required adjacency edge in stable order:
        runs := shared wall runs
        candidates := positions excluding margin/openings
        choose best clearance + circulation alignment
        create OpeningId

WINDOWS:
    for room exterior run:
        usable := run minus margins/doors/structure
        count := choose from usableLength,target spacing
        distribute symmetrically/jittered by seed
        validate every opening

ROOF:
    family := choose allowed family from shape/program/seed
    axes := macro/principal axes
    build roof surfaces/ridges
    validate coverage and positive drainage slope

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
One BuildingPlan candidate is owned by one job until frozen. Batch jobs are independent by BuildingId/SeedPath and merge in stable ID order.

======================================================================
ERROR HANDLING
======================================================================
Bounded solvers return typed failure/fallback reasons and ValidationReport. Invalid building candidates are never partially committed.

======================================================================
DETERMINISM RULES
======================================================================
Candidate order, tie-breaking and RNG streams are stable by semantic IDs. Worker count and hash-map iteration do not affect the plan.

======================================================================
PERFORMANCE RULES
======================================================================
Use bounded candidate sets, spatial/prefix structures and scratch arenas. No unbounded backtracking. Batch independent buildings over JobSystem.
