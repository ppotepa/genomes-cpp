======================================================================
PUBLIC CONTRACTS
======================================================================
1. Combat inputs are commands/intents with tick/source EntityId/sequence. Systems communicate through typed buffers: AimIntent, WeaponIntent, FireIntent, FireRequest, ImpactEvent, DamageCommand, Death/StateEvent.

2. WeaponHandling validates readiness then emits FireIntent. CombatSystem resolves authoritative muzzle/aim/ammo and produces Ballistics FireRequest once.

3. Ballistics ImpactEvent is routed by semantic target type/ID to InfantryDamage, StructuralDamage, generic material consumer; no callbacks into render objects.

4. Event order at commit uses deterministic key (SimulationTick, phase, source stable ID, sequence).

5. Presentation subscribes to committed combat events for muzzle/VFX/audio but cannot alter hit outcome.

======================================================================
DATA LAYOUT
======================================================================
Commands POD-like, short-lived frame/tick arenas. Event payloads IDs + vectors/energies/semantic refs, no owning pointers.

PSEUDOCODE
======================================================================
TICK PHASES:
    orders/AI -> WeaponIntent
    locomotion/pose -> authoritative attachments/hit volumes
    weaponHandling -> FireIntent
    stable commit FireIntents
    combat -> Ballistics FireRequest
    ballistics.step -> ImpactEvents
    stable commit ImpactEvents
    route -> DamageCommands
    destruction/infantry damage commit
    publish CombatPresentationEvents

FIRE:
    pose := authoritativePose(entity)
    muzzleWorld := entityTransform * poseBone * weaponArtifact.muzzleLocal
    request.seed := H(matchSeed, entityId, shotSequence, tick)
    ballistics.enqueue(request)

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Each phase creates parallel local buffers then deterministic barriers. Avoid synchronous recursive subsystem calls across workers.

======================================================================
ERROR HANDLING
======================================================================
Stale entity/weapon/ammo/target returns typed rejection event/diagnostic. Duplicate FireIntent sequence idempotently rejected.

======================================================================
DETERMINISM RULES
======================================================================
Phase/order explicit; seed derived from semantic IDs. Renderer absent yields same outcomes.

======================================================================
PERFORMANCE RULES
======================================================================
Batch commands; no heap per event; use frame arenas/ring buffers. Benchmark 10k fire intents and impacts.

======================================================================
MIGRATION / COMPATIBILITY
======================================================================
Replace SOURCE onShot callback bridge with typed event flow while preserving behavior.
