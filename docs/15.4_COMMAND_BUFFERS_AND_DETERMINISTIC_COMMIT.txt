======================================================================
PUBLIC CONTRACTS
======================================================================
1. Commands have stable type, target/source IDs, phase/tick and SemanticSequenceKey derived from source system/entity/local ordinal. Completion time/thread index is never sequence.

2. Structural commands: CreateEntity, DestroyEntity, Add/RemoveComponent, Set archetype initialization. Domain commands later extend via typed event channels rather than a giant variant if scalability demands.

3. Conflicts have explicit policy per command class: Destroy dominates later mutation; duplicate Add may error/coalesce; create IDs assigned at commit in stable request order or preallocated deterministic token.

4. Thread/job local buffers use scratch; gather then stable radix/sort only when ordering conflict can affect semantics.

======================================================================
PSEUDOCODE
======================================================================
WRITER:
    key := {phase,system,source,localOrdinal++}
    local.push(Command(key,...))

COMMIT:
    commands := concatenate locals
    stableSort(commands,key)
    for command:
        if target already destroyed: ignore/report by policy
        validate
        apply structural/domain command
    resolve createTokens

======================================================================
THREADING / OWNERSHIP RULES
======================================================================
Writers local/no locks. Only commit owner mutates ECS structure. Commit itself may parallelize disjoint targets only after deterministic conflict grouping.

======================================================================
ERROR HANDLING
======================================================================
Invalid/stale entity handles and illegal structural mutation return typed errors or development assertions; expected gameplay failures are not exceptions.

======================================================================
DETERMINISM RULES
======================================================================
Same semantic inputs produce same command order regardless scheduler. Entity create resolution stable.

======================================================================
PERFORMANCE RULES
======================================================================
